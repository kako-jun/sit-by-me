Sit by Me のフィールド背景を、手作りのジオラマ（模型）に見える一枚絵として、生成 → 確認 → 保存 → 歩行マスクの順で作る。敵・召喚獣は `sit-world`、人物は `sit-characters`。このスキルは、**フィールドの背景だけ**。

先に `docs/content-registry.md` から対象の `MAP` ID を確定し、`docs/map-asset-registry.md` のその**1行だけ**の接続契約を読む。続けて `docs/map-topology.md` の**北上固定の大域配置**と、対象が寺町なら**寺町の地形不変条件**、`docs/art-direction.md`（背景の項）、`docs/assets-policy.md`、`docs/decisions.md`（2026-10-14 のジオラマの行）を読み、何がすでに決まっているかを確かめる。台帳の状態が `ready` でなければ生成しない。大域配置から導かれた方向と個別契約が食い違う場合も `blocked` に戻す。承認済みの見本は `sample/field/diorama-trial/teramachi-wide-road-diorama.png`。`sample/field/teramachi-*.png` の4枚は、実写寄りの試作サンプルで、ジオラマ風ではない。

## 目標の見た目（kako-jun 承認済み、2026-10-14）

- **写真に見えてはいけない。** 身近な材料で無理やり再現した、手作りの模型に見えること。
- ジオラマの**土台の板と、まわりの部屋が見えたまま**にする（切り取らない。見えているとAIくさくなくなる）。
- 構図は**奥行きなし**: 左右に広く、上下（奥行き）は浅く、カメラは**真上に近い見下ろし**（約80〜85°。建物の側面が少し見えてよい）。消失点・遠景・空は入れない。道や路面は、画面を水平に横切る**広くてはっきり読める帯**にする（アクスタが立つ面で、キャラの大きさが奥行きと衝突しないため）。人物・文字は入れない。

## 1枚ごとの個性

同じ場所の背景を複数作るとき、**似たような画像を作らない**（kako-jun 指示、2026-10-14）。見た目（材料・光・土台の見え方）はそろえるが、**絵の中身は1枚ごとに、その絵が必要な理由になる個性（主役・地形・ランドマーク）を持たせる**。「別アングルの同じ場所」に見えたら失敗。**歩く方向（道の向き）も1枚ごとに変える**: 横（左右）ばかりにせず、縦（上下）、斜め、L字・T字に曲がる・交わる形を混ぜる（kako-jun 指示、2026-10-14）。縦の道でも、真上に近い見下ろしなので遠近で細くしない（幅は一定）。生成前に、各カットの個性を一行で決める（例: 広い道路＝水平に走る主道路と消雪パイプ、接続画＝角と石橋、狭い道＝土塀にはさまれた路地と山門）。

## つなぎ目の精度は「方向がなんとなく合っている」程度でよい

絵と絵のつなぎ目は、**道の向きがなんとなく合っていればよい**。位置・幅・傾きの厳密な一致や、端での路面の連続は**不要**（kako-jun 指示、2026-10-14。ジオラマなので、別のジオラマに視点が移るものとして、フェードで切り替える。土台の板が縁に見える以上、絵の中では連続しない）。生成は位置や傾きの指定を守らないことがあるので、厳密に合わせようとして再生成を重ねない。規則は、「反対の辺から入る」と「道の向き（横・縦・斜め）が大きく食い違わない」の2つだけを守る。位置はエンジンが相対位置で合わせる。

## 接続路を先に固定する（行き止まりは後）

**まず物語上必須の接続路だけを設計する。** 宝箱用の行き止まりは、必須の接続が全て成立し、画面内に安全な余白があるときだけ足す任意の内側の枝である。行き止まりを作るために、必要な接続を曲げたり、画像端に余計な道路を出したりしてはならない（kako-jun 指示、2026-10-15）。

生成前に、対象カットごとに次の **接続契約** を書く。プロンプトにもそのまま転記する。

| 区分 | 必ず決めること |
|---|---|
| 必須接続 | 接続先、出入りする画像辺、道の向き、道が端まで届く幅のある通路 |
| 端の禁止 | 道・橋・遊歩道を出してはいけない画像辺。必須接続以外は端まで道を届かせない |
| 任意の枝 | 宝箱用なら「画面内で確実に終わる短い枝」と明記し、必須接続とは別にする。余白がなければ作らない |
| 通行不能物 | 川、柵、塀、建物、深雪、段差、石垣、電柱など。車椅子で通す必須路の上・出口・入口には置かない |

描画を確認するときは、(1) 必須接続の本数と出る辺が地図と一致する、(2) 禁止辺に道路が出ていない、(3) 川・橋・柵が必須路を遮断していない、(4) 任意の枝がなくても主経路が完結する、を必ず確認する。曖昧な地名・川・橋の位置は生成前に地図へ戻り、実際の導線と照合してから進める。

## 山・丘・大きな坂は蛇行させる

卯辰山、能登の集落間、兼六園・金沢城の高低差など、上り下りを描くMAPでは、主路を端から端への直線にしない。必須路は**少なくとも一度は左右の向きを変える緩い蛇行またはヘアピン**にする（例: 左カーブ→折返し→右カーブ）。これは景観の変化をつくるだけでなく、勾配を緩くして車椅子の主路を成立させるための規則である。

石段は、立てる時期だけの近道か、通行不能な景観の脇道に限定する。車椅子の必須接続を石段・瓦礫・深雪・急坂で代替してはならない。蛇行しても、画像端の接続方位は `map-topology.md` の北上固定グラフを優先し、宝箱の短枝は主路の外で画面内に終える。

## 先にマップのトポロジーを作る（清書は後）

背景を作る前に、**マップのトポロジー**（どの場所がどの場所と、どの辺の、どの向きの道でつながるか。幅・位置は目安でよい）を、**先に決める**（kako-jun の反省、2026-10-14。絵を先に作ってからつなぐと、道の向きが合わず、足りない絵や再生成が増えた）。手順: (1) 場所の一覧と個性、(2) 場所どうしのつながり（グラフ）と、各つなぎ目の辺と道の向き（横・縦・斜め。傾きや幅・位置は目安）、(3) 事故の前後など状態による通れ方の違い（立てる時期／車椅子の時期）と、手を貸すイベントの区間、(4) それを `teramachi-map.json` と同じ形式の地図（`missing` つき）に書く、(5) 各絵を、つなぎ目の辺と道の向きをプロンプトに入れて、1枚ずつ生成する（清書。位置や幅はぴったり合わなくてよい。上の「つなぎ目の精度」に従う）。同じ町に絵が10枚前後になるので、最初に地図を引く。

## 通路的な背景は少なく、場所に個性を

何もない通路的な背景（道だけの絵）は、1つの町につき**せいぜい1つ**にする（kako-jun 指示、2026-10-14）。残りは、物語で使う**具体的な場所**にする（例: 寺町なら、寺の幼稚園、煙突のある銭湯、坂をのぼった段丘の上）。場所を決めてから、その場所の個性（ランドマーク）、道の向き、端のリンクを決める。

## 材料（プロンプトに必ず名指しする）

| 対象 | 材料 |
|---|---|
| 雪 | 本物の綿（繊維が見える） |
| 木 | スポンジ・毛糸・ドライフラワーを丸めた塊に着色。鉄道模型の木のように明らかに簡略化 |
| 建物 | 厚紙・段ボール・紙粘土（屋根は段ボールの波、壁は指跡・ヘラ跡） |
| 塀・石垣 | 紙粘土や発泡スチロールに粗く描いた石 |
| 道路 | 黒い画用紙か紙やすりに、薄い透明のニス |
| 用水 | 青いセロファンか透明レジン |
| 電柱 | 割り箸（先を色紙で巻く） |
| スノーポール | 赤白のテープを巻いた爪楊枝 |
| 小物（散水ヘッドなど） | ビーズ・ボタン |

手作りの粗も指定する: 接着剤のはみ出し、糸くず、手で切った紙のギザギザの縁、塗りムラ、材料の接ぎ目、画面の縁に見える段ボールの土台、室内の素直な机の上の光、粗い粒子。

## 手順

1. プロンプトを、(a) `MAP` 行の**一言特徴（画面の主役）**、(b) 北上固定の大域配置から導く画像端の方角、(c) `MAP` 行の時期・場所・主経路・禁止辺・通行条件、(d) `art-direction.md`／`assets-policy.md` の共通方針、(e) このスキルの材料・構図規約、の順に組み立てる。「ただの道」だけのMAPは生成しない。台帳にない情報を補わない。既存の実写寄りの画像があれば、**題材と配置の参考としてだけ**参照画像に渡し、「写真の精密な質感・反射・木目を引き継がない」と明記する。
2. `/image` スキル（Skill ツールで image）で生成する。gpt-image-2 を codex exec 経由で `$imagegen` を明示起動する（起動しないと偽造PNGを掴まされる）。
3. **1枚だけ生成して、kako-jun に見せる。自動で再生成しない**（kako-jun は破棄が増えるのを無駄と考える）。見せるときに、接続契約の4点と、模型に見えるか・奥行きが浅いか・人物/文字なし・路面が広く読めるかを自己評価として添える。再生成は kako-jun が求めたときだけ、下の「弱点」を強めた指示で1回。
4. 保存: 試作は `sample/field/diorama-trial/`、採用は `sample/field/` に。`git add` は名指し（`git add -A` 禁止）、Co-Authored-By を付けない。
5. 採用後、その背景の**歩行マスク**を作る（背景ごとに必須）。方式は `docs/systems.md`「歩ける場所のマスク」と `.claude/skills/sit-field-mask/SKILL.md` に従う。`sample/field/masks/` の `make_masks.py` は、Photoshop編集用の塗りだけの `*-traversal-edit.png`（黒=誰も通れない、橙=立てる時期または相方の介助解禁後だけ、白=全員）を正本として、各実行時マスクを作る。前景の被さりは別の `*-foreground-edit.png` / `*-foreground-mask.png` にし、通行判定に混ぜない。JSONは背景・サイズ・リンクなどを記録し、初回用のポリゴン下書きは任意とする。端のリンク用に、道が画像の端に届く区間とその通行クラスを `links` に記す（土台の板の外側にはリンクを置けない）。
6. `*-mask-overlay.png` は輪郭入りの確認専用プレビューである。これを kako-jun に見せ、輪郭なし編集マップを直して `uv run --with pillow python3 sample/field/masks/make_masks.py` を再実行する。編集マップ自体に輪郭を描かない。JSONの初期下書きから意図して作り直す時だけ `--refresh-edit` を指定する。

## 弱点（kako-jun が求めたときだけ強める）

- 路面が濡れたアスファルトの反射のままになりやすい → 黒い画用紙に、つや消しの薄いニス、と強める。
- 石垣・土塀・木壁が整いすぎる → 荒削りの紙粘土、と強める。
- 紙の縁のギザギザと接着剤のはみ出しが弱い → 目立たせる。

## 記録

- 採用したら、Issue #11（背景）に、保存先・見た目・使った参照画像を記録する。
- 手順や弱点に新しい学びがあれば、このスキルに追記する（成長資産）。

## 禁止事項

- Co-Authored-By をコミットメッセージに付けない
- `--no-verify` を使わない
- 生成画像について、独自に性的・不適切の判定をして削除・停止しない（そのまま報告する）
- 指示されていない再生成をしない
- `python3` の直接実行をしない（`uv run python3`）
