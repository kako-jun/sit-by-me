**画像の保存形式（#68決定、2026-10-19）**: imagegenの出力（PNG）→切り出し→**WebP（非可逆・品質85・アルファ保持）**にして正本パスへ保存する（`magick in.png -quality 85 out.webp`、または `verification/characters/tools/key_*.py` が直接WebPで出す）。PNGは残さない（name-name のTUIは WebP のみデコードできる）。実寸（不変）・アルファ（`magick in.png -alpha extract` と変換後WebPの同コマンドを `compare -metric AE` で比べAE=0）の検査はWebPで行う。寸法ゲートの基準（1920×1080等）は変えない。 マスク・編集マップなど厳密な画素が要るものは**可逆WebP**（`-define webp:lossless=true`）で保存し、PNGは残さない。 MAPの既存PNG（fields/legacy・masks）はMAP改名PR（PR-M）でWebP化するまで現状のまま。

Sit by Me のフィールド背景を、手作りのミニチュアに見える一枚絵として、生成 → 確認 → 保存 → 歩行マスクの順で作る。敵は `sit-enemy-sprite`、召喚獣は `sit-summon-sprite`、人物は `sit-character-sprite`、戦闘背景は `sit-battle-background` を使う。このスキルは、**フィールド背景だけ**。

## モック提示ゲート（絶対・最優先。このスキルの全行より優先）

kako-jun 指示（2026-10-22、逐語）: 『モックを見せずに作ることはスキルで禁止にしろ』。

1. **承認なしの画像生成は禁止。** imagegen を呼ぶ全て（試験生成・1枚だけの試作・並行生成を含む）の前に、対象エリア／グループの**全MAPのモック**（割付図・接続・各MAPの道の形と向き）を kako-jun に一度見せ、**明示の承認**を得る。『仮案だが機械検査OK』『レビューが可と言った』『試験だから1枚だけ』は理由にならない。
2. **見せ方**: 全MAPを1枚の一覧（体の配置・地図の配置に沿った並べ）と、接続表で見せる。承認の記録（日付・承認された版の hash／ファイル）を Issue に残す。承認後にモックを変えたら再承認が要る。
3. **原文の形語彙を機械導出で置換しない。** 原文に『斜め』『一本道』『右上』等の形・方位語があるMAPは、その語を割付図でそのまま実現し、機械導出で別の形（L字・直線）にしない。モックには、原文の形語彙と1行ずつ照合した表を添える。導出が必要な未決は『仮案』と明記して見せ、承認を得る。
4. **土台縁・机・遷移範囲**: モックには土台縁と机の余白を必須で載せる。通路は画像端でなく模型の縁まで届かせ、遷移は辺上の範囲指定にする。画像全面ベタの割付図は禁止。
5. **並行生成の条件**: 『モック承認済み＋代表1枚を kako-jun が見て承認済み』のときだけ許可する。
6. **保留MAP（原文未確定）**: 形を発明しない。モックには『未確定』枠で載せ、kako-jun に決めてもらう。
7. 違反例（2026-10-22 体内）: 手足を L字・縦直線のモックのまま BDY-10 を試験生成し、12枚の並行生成まで進めた。『斜めに伸びる道でないと』と却下された。

## 一意解釈ゲート（モック提示ゲートの次に優先）

このゲートは曖昧語だけで形状・幅・方角を決めることを禁じる。原文の逐語引用、対象の名詞、材料・加工法、建築の包含・配置・内部接続の意味は省いてはならない。原文にある直線・曲線はそのまま使う。

生成入力・検査では原文の名詞・材料・配置関係を保持し、形状の根拠を原文、参照画像、MAP ID、座標、画像端、数、色、定義済み方角で特定する。`少し`、`やや`、`広い`、`狭い`、`近い`、`遠い`、`自然`、`十分`、`明瞭`、`目立つ`、`適切`、`雰囲気`、`おおよそ`、`〜風`、`斜め`だけ、`奥行き`だけ、`つながる`だけを実行語にしない。原文にある語は削らず引用し、曖昧な条件は対象物・始終点・向き・参照または原文にある数値へ対応づける。根拠がなければTBDを残して停止し、数値を発明しない。

道・水路・廊下・建物の形を「読みやすさ」「規則性」「生成しやすさ」を理由に直線、直交、格子、等間隔へ正規化してはならない。台帳または参照MAPに書かれた辺・曲がり・端だけを描く。原文にない経路、交差、直角、曲線を追加してはならない。

## ミニチュア材料・道具の固定宣言

「手作り」「模型」「ジオラマ」だけを書いて生成してはならない。各生成入力には、対象ごとに使う材料、加工道具、接着方法を明記し、画像でもその材料が判別できなければ失格とする。既定の工作語彙は次だけを使う: 土台=`5 mm foamboard` と露出した `corrugated cardboard` 断面、壁・石=`paper clay` を爪楊枝で刻む、屋根=`corrugated cardboard`、道=`black construction paper` または `sandpaper`、雪=`cotton batting` とPVA接着剤、木=`green sponge`・毛糸・細針金、用水=`blue cellophane` または透明レジン、柱=`wooden toothpick`、固定=`masking tape`・白いPVA接着剤、着色=`matte poster paint` と平筆。各候補は必要なものだけを選び、材料名・道具名・加工法を生成入力に列挙する。

実物のアスファルト、実物の雪、実物の瓦、実物の木、CGの均一表面、素材不明の「ミニチュア風」を出してはならない。原寸検査で、土台断面・切断面・テープ・接着剤・指定材料のうち少なくとも三つが原寸画像で確認できるか検査する。確認できなければ `failed` として記録し、合格候補・mask・参照への昇格を止める。

先に `docs/content-registry.md` から対象MAPを確定し、対象台帳・仕様・相互接続・地形不変条件・共通美術規約を読む。生成可否は本スキルの「寸法・工程・来歴」で判定する。大域配置と個別契約が食い違えば生成前に解消する。旧試作は現在の合格証拠にしない。

生成直前に、原文の各項目を省略せず「原文 → プロンプト中の対応文」として照合する。対応できない原文が一つでもあれば生成を止める。画像の見栄え、過去候補、生成器の都合、作業速度は、このゲートを越える理由にならない。

## 建築連続性ゲート（寺・学校・住宅など、複数MAPが一建物を表す場合）

接続表にある扉のリンクだけを満たして「建築がつながった」と判断してはならない。生成前に、対象建物群の**原文に書かれた建築順序・包含関係・内部限定の移動**を、削らず一行ずつ `建築不変表` に転記する。主担当・サブエージェントは、その表を自分の要約で置き換えてはならない。

### 外観と内部を混ぜない

| 生成対象 | 絶対条件 |
|---|---|
| 外観／境内MAP | 建物は屋根・外壁を保った外観として描く。屋根を外して内部の部屋、廊下、家具、断面を見せない。内部MAP間の移動を説明するために外部渡り廊下・屋外通路・別棟を足さない。 |
| 内部MAP | そのMAPの室内だけを描く。空、雪、庭、屋外敷地、外部への偽出口を入れない。接続先は同一建物内の扉または廊下の続きとしてだけ描く。 |

原文またはユーザーが「A と C の間が B」「内部だけで行き来する」「別棟ではない」と指定した場合、その文を**一字も言い換えず**生成入力へ入れ、以下を生成前・生成後に二択で検査する。

1. 外観の屋根量・連続した外壁だけで、A—B—C の順序が読めるか。
2. 屋外へ出る通路（吹きさらしの外部通路）、屋外ドア、離れた別棟、屋根を外した内部表示が混入していないか。屋根と壁のある廊下棟はこれに当たらず、項目4で必須とする。
3. 各内部MAPの扉は、指定された隣室へ続く内部廊下であり、屋外へ出るものに化けていないか。

4. 構成棟（例: 本堂・住居・幼稚園）が、要求どおりの屋根付き廊下で連結して一つの連続した建物群に見えるか。具体基準: 本堂の左右の壁面に屋根付き廊下棟が接する。棟の屋根が本堂・住居・幼稚園の屋根へ切れ目なく続く。廊下棟の両端が壁に接し、地面の隙間・雪原が屋根と屋根の間に通らない。住居と幼稚園の間に直接の廊下がない。吹きさらしの外部渡り廊下は不可、屋根と壁のある廊下棟は必須。

外観参照のpromptは禁止文だけで書かず、つながり・包含関係（どの棟がどの棟と何でつながり、何の中にあるか）を肯定形で書く。「別棟を足さない」のような禁止文だけだと、連結要求と衝突したり、つながりが描かれないまま通る。

一つでも `いいえ` なら、候補は失敗である。見た目が良くても保存先へ採用候補として進めず、次のMAP生成にも使わない。建築順序を原文から確定できない場合は、画像生成ではなく原文の矛盾を報告して停止する。

### 同一建物群の生成順序

同一建物群は、まず屋根・外壁を保った外観参照候補を1枚だけ作り、建築不変表との独立確認を通す。通過まで内部MAPを生成しない。室内候補には通過済み外観を建築・材料参照として入力し、室内形状と扉方向は原文から取る。見えない間取りを画像から推測しない。#60では住居↔本堂↔幼稚園を内部だけで接続し、住居↔幼稚園の直結を廃止する。屋根形・寸法・方角はこの順序だけから創作しない。別敷地の原文に存在する独立建物まで禁止する規則ではない。

## 目標の見た目（kako-jun 承認済み、2026-10-14）

- **写真に見えてはいけない。** 身近な材料で無理やり再現した、手作りの模型に見えること。
- ジオラマの**土台の板と、まわりの部屋が見えたまま**にする（切り取らない。見えているとAIくさくなくなる）。
- カメラの鉛直下向き角は、45°より急な、できるだけ真上寄りとする（数値は要確認。斜めは許容）。手前に出る物はレイヤー分離せず、後工程のマスクで処理する。空、地平線、消失点を入れない。道路・路面の始点、終点、幅、画像端は対象MAPの原文とmask座標だけを使う。人物と文字を入れない。

## 1枚ごとの個性

同一地区の各MAPは、対象MAP行の一言特徴・必須接続・禁止辺・参照IDが一致しない別の組合せを持つ。道の始点、終点、曲がり、画像端は対象MAP原文だけを使う。MAP原文に無いL字、T字、交差、直線、曲線を追加しない。生成前に、対象MAP行を生成入力へ原文のまま添付する。

## 接続判定は接続表だけを使う

接続判定は、`map-topology.md` に記録された接続元MAP・接続元辺・接続先MAP・接続先辺が一致するかだけで行う。画像間の路面位置、路面幅、路面角度を新規の一致条件にしない。接続表に無い辺（模型の縁）へ路面を出さない。通路は画像端でなく模型の縁まで届かせ、土台の板とまわりの机を見えたままにする（kako-jun 2026-10-22）。

## 接続路を先に固定する（行き止まりは後）

**まず物語上必須の接続路だけを設計する。** 宝箱用の行き止まりは、必須の接続が全て成立し、画面内に安全な余白があるときだけ足す任意の内側の枝である。行き止まりを作るために、必要な接続を曲げたり、画像端に余計な道路を出したりしてはならない（kako-jun 指示、2026-10-15）。

生成前に、対象カットごとに次の **接続契約** を書く。プロンプトにもそのまま転記する。

| 区分 | 必ず決めること |
|---|---|
| 必須接続 | 接続先、出入りする画像辺、道の向き、道が模型（ジオラマ）の縁の辺まで届く幅のある通路（画像端まで届かせない。遷移位置は辺上の範囲指定、範囲値TBD） |
| 端の禁止 | 道・橋・遊歩道を出してはいけない画像辺。必須接続以外は模型の縁まで道を届かせない |
| 任意の枝 | 宝箱用なら「画面内で確実に終わる短い枝」と明記し、必須接続とは別にする。余白がなければ作らない |
| 通行不能物 | 川、柵、塀、建物、深雪、段差、石垣、電柱など。車椅子で通す必須路の上・出口・入口には置かない |

描画を確認するときは、(1) 必須接続の本数と出る辺が地図と一致する、(2) 禁止辺に道路が出ていない、(3) 川・橋・柵が必須路を遮断していない、(4) 任意の枝がなくても主経路が完結する、を必ず確認する。曖昧な地名・川・橋の位置は生成前に地図へ戻り、実際の導線と照合してから進める。

## 山・丘・大きな坂は蛇行させる

卯辰山、能登の集落間、兼六園・金沢城の高低差など、上り下りを描くMAPでは、主路を端から端への直線にしない。必須路は**少なくとも一度は左右の向きを変える緩い蛇行またはヘアピン**にする（例: 左カーブ→折返し→右カーブ）。これは景観の変化をつくるだけでなく、勾配を緩くして車椅子の主路を成立させるための規則である。

石段は、立てる時期だけの近道か、通行不能な景観の脇道に限定する。車椅子の必須接続を石段・瓦礫・深雪・急坂で代替してはならない。蛇行しても、画像端の接続方位は `map-topology.md` の北上固定グラフを優先し、宝箱の短枝は主路の外で画面内に終える。

## 先にマップのトポロジーを作る（清書は後）

背景を生成する前に、対象MAPの接続元・接続元辺・接続先・接続先辺・時期条件・通行クラスを `map-topology.md` と対象MAP契約から取得する。幅、位置、曲がりは原文または既存mask座標に数値がある場合だけ使う。数値が無い場合に形状を補完しない。各画像は1回ずつ生成し、原文束を生成入力に添付する。

## 通路的な背景は少なく、場所に個性を

何もない通路的な背景（道だけの絵）は、1つの町につき**せいぜい1つ**にする（kako-jun 指示、2026-10-14）。残りは、物語で使う**具体的な場所**にする（例: 寺町なら、寺の幼稚園、煙突のある銭湯、坂をのぼった段丘の上）。場所を決めてから、その場所の個性（ランドマーク）、道の向き、端のリンクを決める。

## 手順

1. `台帳原文ゲート` を通過した原文束を、削除・要約・推測なしにプロンプトへ添付する。その後にだけ、(a) `MAP` 行の**一言特徴（画面の主役）**、(b) 北上固定の大域配置から導く画像端の方角、(c) `MAP` 行の時期・場所・主経路・禁止辺・通行条件、(d) `art-direction.md`／`assets-policy.md` の共通方針、(e) このスキルの材料・構図規約、の順に原文対応を明示して組み立てる。「ただの道」だけのMAPは生成しない。台帳にない情報を補わない。既存の実写寄りの画像があれば、**題材と配置の参考としてだけ**参照画像に渡し、「写真の精密な質感・反射・木目を引き継がない」と明記する。
2. 利用可能な `imagegen` スキルを読み、組み込み `image_gen` で生成する。参照は実画像として入力する。存在しないモデル・quality・size引数や古い `codex exec` 手順を必須にしない。利用不能なら原因を記録して停止する。返却原本を測定し、promptの寸法指定だけで通過させない。
3. **モック提示ゲート承認済みであることを確認してから**、1枚だけ生成して、kako-jun に見せる（承認前の試験生成は禁止）。自動で再生成しない。見せるときは、接続先MAP、接続辺、禁止辺、通行クラス、人物なし、文字なし、材料名、土台断面の有無を列挙する。再生成は kako-jun が求めたときだけ、原文束と材料宣言を再入力して1回行う。
4. 保存: 新規本制作の正本は `assets/images/fields/TRM-01.webp` 等、台帳のMAP ID（区域コード3字-2桁連番。旧E/F/N IDは[対応表](../../../docs/production/20261019-map-id-renumber.json)）を使う。生成物は台帳のIDの正本パスへ直接上書きし、候補置き場・版suffix・検証用サンプル画像の新規作成はしない。保存は直接上書き: 生成物はサンプル・候補の置き場に置かず、ゲームで使う正本パスへ直接上書きする（#68決定、2026-10-19）。合格ならコミット、不合格・不採用は `git restore <path>`（未追跡の新規ファイルは即削除）でリバートし、不採用・失敗画像は置き場に残さない。**使う可能性のあるテイクは、次を生成する前にコミットする**（未コミットの新規ファイルは次の上書きで消える）。`git add` は名指し。採用状態は置き場でなく台帳のstatusで管理する。 既存の `legacy/`（旧素材）は現状維持で、新規生成先にしない。旧検証画像 VFIELD* は削除済み（復元は git 履歴 `1bb09d0` から）。`reference/`（外観参照専用、平置き・kebab-case）は参照画像としてのみ使い、生成物の置き場にしない。参照として残す画像は長辺を下げた縮小版にして役割が分かる名前へリネームして保存する（上限px・形式は未決＝要確認、決定までは新規保存しない）。不採用・失敗画像は残さず削除する。図解は `assets/images/diagrams/DIAGxxx.png`。
5. 独立生画像レビュー通過後、採用前にその背景の**歩行マスク**を作る（背景ごとに必須）。方式は `docs/systems.md`「歩ける場所のマスク」と `.claude/skills/sit-field-mask/SKILL.md` に従う。旧生成ツール `make_masks.py`（#68の整理で削除。必要なら git 履歴 `1bb09d0:verification/fields/legacy-masks/make_masks.py` から復元）は、Photoshop編集用の塗りだけの `*-traversal-edit.png`（黒=誰も通れない、橙=立てる時期または相方の介助解禁後だけ、白=全員）を正本として、各実行時マスクを作る。前景の被さりは別の `*-foreground-edit.png` / `*-foreground-mask.png` にし、通行判定に混ぜない。JSONは背景・サイズ・リンクなどを記録し、初回用のポリゴン下書きは任意とする。端のリンク用に、道が画像の端に届く区間とその通行クラスを `links` に記す（土台の板の外側にはリンクを置けない）。
6. `*-mask-overlay.png` は輪郭入りの確認専用プレビューである。これを kako-jun に見せ、輪郭なし編集マップを直して マスク生成ツールを再実行する。編集マップ自体に輪郭を描かない。JSONの初期下書きから意図して作り直す時だけ `--refresh-edit` を指定する。

## 装飾密度の基準（kako-jun 2026-10-22）

寺町の幼稚園（TRM-02採用画像）級の情報密度を求める。**体内BDYの装飾は人体に関係する抽象的な工作物だけ**（下の『装飾はMAPごとに変える』の8族。花・葉・雲・星・旗・柵・ハート形・動物・食べ物・風景は使わない。kako-jun 2026-10-22「人体と関係ない花とか雲を使うのはやめろ」）。装飾を**最初の prompt から**含める（後から足す前提にしない）。装飾は地形・縁・机だけに置き、歩く床は空ける。机は木目にする。

## 弱点（kako-jun が求めたときだけ強める）

- 路面が濡れたアスファルトの反射のままになりやすい → 黒い画用紙に、つや消しの薄いニス、と強める。
- 石垣・土塀・木壁が整いすぎる → 荒削りの紙粘土、と強める。
- 紙の縁のギザギザと接着剤のはみ出しが弱い → 目立たせる。

## 教訓（BDY-02、2026-10-22）

モック提示ゲート・原文の形語彙の保持・割付図の余白と土台縁・通路の届かせ方は冒頭の『モック提示ゲート』に集約した。ここにはそれ以外の教訓だけを残す。

1. 中央の広間に台座を足さない。壁に見えて行き止まりと誤読される。
2. 床の幅は壁の内側基準で指定する。壁・毛糸の厚みで、実際の床は10〜20%細くなる。細い通路（BDY-09 は230px）では壁を細く低くする（段ボール帯1本・幅約12px・毛糸の縁取りは床の幅に含めない）。壁を太く描かれると床が痩せる（BDY-09 の簡素な背景の最初の生成で床が約7割に痩せ、床IoU 0.686）。
3. 地形の厚塗りは肉の断面に見えうる。薄く平らな面にする。
4. 評価が「かなりいい」になったら作り直さない。編集元を固定して装飾だけ足す1回の編集で密度を上げ、幾何が動いていないことを床マスクIoUで検査する。
5. 生成時の参照コピーは必ず現行ファイルを渡し、渡す前にsha256を照合する。並行生成は『モック承認済み＋代表1枚を kako-jun が見て承認済み』の後にだけ許可する。
6. 装飾密度の基準は『装飾密度の基準』節に従う。
7. **imagegenの画像保存失敗は標準手順で回収する**（体内BDYの実測で5回中3回発生）。codex の返却に保存パスが無い・`out/` にファイルが無いときは、codex のセッションID（codex.log の `session id:`）と**一致する** `~/.codex/generated_images/<セッションID>/` の生成物を、**無加工のまま**（リサイズ・変換・加工なし）`out/` へコピーして回収する。他のセッション・他の呼び出しの生成物は使わない（並行時は特に。ID不一致なら回収しない）。回収したら実寸と sha256 を記録する。
8. **並行エージェントの作業ファイル名は MAP・エージェントごとに固有にする**。scratchpad の `runall.sh`・`send.txt`・`ref1.png` のような共有名を複数エージェントが使うと、codex が重複起動した（衝突の実例）。`run-bdy07.sh`・`bdy07-send.txt`・`bdy07-ref1.png` のように MAP ID（と担当）を名前に入れ、ディレクトリも `bdyNNop/` と MAP ごとに分ける。

## 体内BDYの生成方式（装飾込みの1回生成 = onepass。2026-10-22）

**2段階生成（簡素な背景の段階1→装飾の段階2）は廃止した（kako-jun 指示 2026-10-22「簡素な背景で一度作ってからやり直すのをやめろよ」）。** 理由・経緯: 簡素な背景を作ってから作り直すのは手間がかかる。過去の装飾込み1回生成は幾何が崩れた（BDY-02 neck-v1 は床IoU 0.775、BDY-10 は床IoU 0.303）が、**どちらも様式参照画像（BDY-10 試験画像=参照3）を渡していた**。様式参照なし・参照2枚（clean 割付図＋材料見本）だけの構造 prompt は幾何が保たれた（BDY-02 の簡素な生成は床IoU 0.92）。そこで仮説「様式参照画像が幾何を崩す主因」を立て、様式参照なしの1回生成を既定にした。検証結果は BDY-09 で記録する（下の『検証記録』）。

### onepass の手順

1. `build_body_prompt.py BDY-xx --out verification/body-layout/prompts`（または `--all`）で `BDY-xx-prompt.md` と `BDY-xx-prompt-send.txt` を作る。`--stage` は廃止。
2. 参照は**2枚だけ**: 1=clean 割付図、2=材料見本。**様式参照画像は渡さない**。様式（人体に関係する抽象的な工作物＝骨・細胞・筋肉の糸・鼓動線・皮膚・ばんそうこう・毛・ばい菌、PVAの垂れ・tape・木目の机）は本文 P9 の文章だけで伝える。
3. 本文は構造（P1〜P8、P10〜P14）に装飾（P9）を足したもの。壁・仕切りは床の外側に立つ細く低い corrugated cardboard の帯1本（幅約12px、1672x941では約10px）＋毛糸の縁取り1本（クリームか薄桃。床の幅に含めない）。床の幅は clean の床の領域の幅（230px、1672x941では約200px）を保つ（P6）。**土台縁の帯と机は四辺すべてに見える**（P1・P2・REFERENCE・検査項目で肯定形に強めた: 『画面の四辺すべてで、外周に木目の机、その内側にクリームの foamboard の縁取り帯、その内側に波形の段ボール断面が見える。模型の天面は画像の内側に収まり、縁に接しない』。実測で N辺・S辺の縁取り・波形が0pxの MAP が多かった）。装飾は地形・壁際・土台縁・机にだけ置く。密度は寺町の幼稚園級（地形の面積に比例。少なくとも6か所の塊・各塊3〜5種）。床は何も置かず平ら（P11）。赤い折り紙は**ちょうど6枚**（『Exactly six … no seventh』『数えて6枚』『All six lie on the terrain faces inside the model』＝模型の外・机・床・土台縁の帯には置かない。実測で5枚・8枚（うち2枚は模型の外）が出たため文言を強めた）で、装飾の下敷きにしない（P10）。血管・臓器に見える毛糸の走らせ方はしない（短い別々の糸・渦・縁取りだけ）。
4. 送信文には SOURCE TEXT（逐語）を入れる。`--verify-send` の不一致は0件、内部語チェックはビルダーが出力のたびに行う。
5. 参照2枚を現行ファイルのコピーで置き sha256 を照合してから送る:

```
uv run --with pillow --with numpy python3 -I .claude/skills/sit-field-background/tools/build_body_prompt.py BDY-07 --out verification/body-layout/prompts
codex exec --skip-git-repo-check -s workspace-write -i ref1.png -i ref2.png < BDY-07-prompt-send.txt   # --full-auto は不可。出力名は out/bdyNN-op-v1.png
uv run --with pillow --with numpy --with scipy python3 -I .claude/skills/sit-field-background/tools/check_body_image.py BDY-07 out/bdy07-op-v1.png --out out/bdy07-op-v1-check.png
```

6. 検査: `check_body_image.py` に加えて**床の半透明重ね画像**（緑=一致・赤=期待のみ・青=実測のみ）と床IoU。美観の判定は kako-jun が行う。1回だけ生成し、再試行しない。

### チェッカー（check_body_image.py）

色でなく構造で測る。机・縁は4層（机→縁取り→波形→天面）を行ごとの画素割合で測り、期待との比で判定する（30%未満FAIL・60%未満WARN）。通路は波形内側+14〜+30pxの帯で床区間を数え、本数・中心±25px・幅±10%を比較する。広間は壁の色を見ず、床の途切れ半径を3度刻みで測る（一致85%以上PASS・50%未満FAIL）。床の汚れは従来どおり。生成物の採用相当は PASS か WARN。FAIL があれば再生成、WARN は重ね画像を目視する。**限界**: 机・縁の絵柄が別物だと4層が読めない。広間付きMAPの検証は BDY-02 のみ。
