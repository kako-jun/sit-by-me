## 教訓（BDY-02、2026-10-22。エリア共通のものは pitfalls.md に再掲）

モック提示ゲート・原文の形語彙の保持・割付図の余白と土台縁・通路の届かせ方は冒頭の『モック提示ゲート』に集約した。ここにはそれ以外の教訓だけを残す。

1. 中央の広間に台座を足さない。壁に見えて行き止まりと誤読される。
2. 床の幅は壁の内側基準で指定する。壁・毛糸の厚みで、実際の床は10〜20%細くなる。細い通路（BDY-09 は230px）では壁を細く低くする（段ボール帯1本・幅約12px・毛糸の縁取りは床の幅に含めない）。壁を太く描かれると床が痩せる（BDY-09 の簡素な背景の最初の生成で床が約7割に痩せ、床IoU 0.686）。
3. 地形の厚塗りは肉の断面に見えうる。薄く平らな面にする。
4. 評価が「かなりいい」になったら作り直さない。編集元を固定して装飾だけ足す1回の編集で密度を上げ、幾何が動いていないことを床マスクIoUで検査する。
5. 生成時の参照コピーは必ず現行ファイルを渡し、渡す前にsha256を照合する。並行生成は『モック承認済み＋代表1枚を kako-jun が見て承認済み』の後にだけ許可する。
6. 装飾密度の基準は『装飾密度の基準』節に従う。
7. **imagegenの画像保存失敗は標準手順で回収する**（体内BDYの実測で5回中3回発生）。codex の返却に保存パスが無い・`out/` にファイルが無いときは、codex のセッションID（codex.log の `session id:`）と**一致する** `~/.codex/generated_images/<セッションID>/` の生成物を、**無加工のまま**（リサイズ・変換・加工なし）`out/` へコピーして回収する。他のセッション・他の呼び出しの生成物は使わない（並行時は特に。ID不一致なら回収しない）。回収したら実寸と sha256 を記録する。
8. **並行エージェントの作業ファイル名は MAP・エージェントごとに固有にする**。scratchpad の `runall.sh`・`send.txt`・`ref1.png` のような共有名を複数エージェントが使うと、codex が重複起動した（衝突の実例）。`run-bdy07.sh`・`bdy07-send.txt`・`bdy07-ref1.png` のように MAP ID（と担当）を名前に入れ、ディレクトリも `bdyNNop/` と MAP ごとに分ける。

## 体内BDYの生成方式（装飾込みの1回生成 = onepass。2026-10-22）

**2段階生成（簡素な背景の段階1→装飾の段階2）は廃止した（kako-jun 指示 2026-10-22「簡素な背景で一度作ってからやり直すのをやめろよ」）。** 理由・経緯: 簡素な背景を作ってから作り直すのは手間がかかる。過去の装飾込み1回生成は幾何が崩れた（BDY-02 neck-v1 は床IoU 0.775、BDY-10 は床IoU 0.303）が、**どちらも様式参照画像（BDY-10 試験画像=参照3）を渡していた**。様式参照なし・参照2枚（clean 割付図＋材料見本）だけの構造 prompt は幾何が保たれた（BDY-02 の簡素な生成は床IoU 0.92）。そこで仮説「様式参照画像が幾何を崩す主因」を立て、様式参照なしの1回生成を既定にした。検証結果は BDY-09 で記録する（下の『検証記録』）。

### onepass の手順

1. `build_body_prompt.py BDY-xx --out verification/body-layout/prompts`（または `--all`）で `BDY-xx-prompt.md` と `BDY-xx-prompt-send.txt` を作る。`--stage` は廃止。
2. 参照は**2枚だけ**: 1=clean 割付図、2=材料見本。**様式参照画像は渡さない**。様式（人体に関係する抽象的な工作物＝骨・細胞・筋肉の糸・鼓動線・皮膚・ばんそうこう・毛・ばい菌、PVAの垂れ・tape・木目の机）は本文 P9 の文章だけで伝える。
3. 本文は構造（P1〜P8、P10〜P14）に装飾（P9）を足したもの。壁・仕切りは床の外側に立つ細く低い corrugated cardboard の帯1本（幅約12px、1672x941では約10px）＋毛糸の縁取り1本（クリームか薄桃。床の幅に含めない）。床の幅は clean の床の領域の幅（230px、1672x941では約200px）を保つ（P6）。**土台縁の帯と机は四辺すべてに見える**（P1・P2・REFERENCE・検査項目で肯定形に強めた: 『画面の四辺すべてで、外周に木目の机、その内側にクリームの foamboard の縁取り帯、その内側に波形の段ボール断面が見える。模型の天面は画像の内側に収まり、縁に接しない』。実測で N辺・S辺の縁取り・波形が0pxの MAP が多かった）。装飾は地形・壁際・土台縁・机にだけ置く。密度は寺町の幼稚園級（地形の面積に比例。少なくとも6か所の塊・各塊3〜5種）。床は何も置かず平ら（P11）。赤い折り紙は**ちょうど6枚**（『Exactly six … no seventh』『数えて6枚』『All six lie on the terrain faces inside the model』＝模型の外・机・床・土台縁の帯には置かない。実測で5枚・8枚（うち2枚は模型の外）が出たため文言を強めた）で、装飾の下敷きにしない（P10）。血管・臓器に見える毛糸の走らせ方はしない（短い別々の糸・渦・縁取りだけ）。
4. 送信文には SOURCE TEXT（逐語）を入れる。`--verify-send` の不一致は0件、内部語チェックはビルダーが出力のたびに行う。
5. 参照2枚を現行ファイルのコピーで置き sha256 を照合してから送る:

```

codex exec --skip-git-repo-check -s workspace-write -i ref1.png -i ref2.png < BDY-07-prompt-send.txt   # --full-auto は不可。出力名は out/bdyNN-op-v1.png
uv run --with pillow --with numpy --with scipy python3 -I .claude/skills/sit-field-background/tools/check_body_image.py BDY-07 out/bdy07-op-v1.png --out out/bdy07-op-v1-check.png
```

6. 検査: `check_body_image.py` に加えて**床の半透明重ね画像**（緑=一致・赤=期待のみ・青=実測のみ）と床IoU。美観の判定は kako-jun が行う。1回だけ生成し、再試行しない。

### チェッカー（check_body_image.py）

色でなく構造で測る。机・縁は4層（机→縁取り→波形→天面）を行ごとの画素割合で測り、期待との比で判定する（30%未満FAIL・60%未満WARN）。通路は波形内側+14〜+30pxの帯で床区間を数え、本数・中心±25px・幅±10%を比較する。広間は壁の色を見ず、床の途切れ半径を3度刻みで測る（一致85%以上PASS・50%未満FAIL）。床の汚れは従来どおり。生成物の採用相当は PASS か WARN。FAIL があれば再生成、WARN は重ね画像を目視する。**限界**: 机・縁の絵柄が別物だと4層が読めない。広間付きMAPの検証は BDY-02 のみ。

2026-10-22 の変更（実測で食い違いが出たため）:

- **床色は固定値でなく画像から推定**（`estimate_floor_color`: 天面 rect 内のクリーム系画素の最大連結クラスタの中央値）し、床・通路・赤紙・汚れの全項目で一貫して使う。
- **床IoUの定義を `body_floor_overlay.py` と共通化**（`floor_iou_ov`: 天面 rect を14px内側に縮め、和絶対差<45の床色画素の開閉2回→最大連結、膨張・縁取り補正なし。PASS≧0.75・WARN≧0.60）。旧チェッカーは膨張補正つきで BDY-07 が 0.599、旧 ov.py（scratchpad、床色固定 238,200,158 を手書き）は 0.197 と食い違った。実際の床色は 224,188,148 だった。重ね画像（緑=一致・赤=期待のみ・青=実測のみ）は `uv run --with pillow --with numpy --with scipy python3 -I .claude/skills/sit-field-background/tools/body_floor_overlay.py BDY-07 out/bdy07-op-v1.png` で出す。
- **『色の逸脱』は床領域と地形の地色だけ**を対象にする（床領域の緑・青・強赤の比率、地形の地色の色相・彩度の中央値）。装飾（ビーズ・フェルト）の高彩度は中央値に響かず、誤検出しない。
- **新項目『装飾の色域』**: 地形面積に対する、肌色・薄桃・クリーム・茶系・象牙色の範囲外（緑・青・紫・黄・オレンジ）の画素比率。**2%超でWARN・5%超でFAIL**（赤は折り紙として除外）。重ね画像では濃青で示す。
- **赤紙は『模型の中の枚数』と『模型の外の赤』を別項目**で報告する（外にあれば FAIL。机の上・床の上の赤紙を拾う）。
- 較正（装飾の色域）: BDY-01 緑青黄の庭 9.0% FAIL、BDY-03 0.00%・BDY-09 採用画像 0.00%・BDY-02 採用画像 0.00% は PASS。

- 出口の範囲は縁から内側4pxの帯の white の連続区間。禁止辺の検査も同じ4px帯（『出口でない辺で、縁から内側4px以内と縁の外側に white が無い』）。床が縁に届かない出口だけ30px帯の検出区間（links の `range_definition` に明記）。縁を越えて white が出る出口は `edge_definitions` に rect の縁と前縁の両方を記録（どちらを採るかは TBD）。
- rect（天面の矩形）を読めない辺は期待値へフォールバックし、register の `adoption.rect_fallback_sides` と note に明記する。通路幅・入口の幅の差は『画像の描画による差。マスクは画像に従う』として register に記録する（画像が正）。
- 検査は17枚で自分で数える（寸法・{0,255}・traversal-edit=mask・可逆WebP の VP8L チャンク・白の連結成分1・md>15 の白0・禁止辺・出口の個数と辺・links と実測の一致・BDY-04 の迷路格子）。
