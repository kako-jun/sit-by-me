# Sit by Me 戦闘背景

**画像の保存形式（#68決定、2026-10-19）**: imagegenの出力（PNG）→切り出し→**WebP（非可逆・品質85・アルファ保持）**にして正本パスへ保存する（`magick in.png -quality 85 out.webp`、または `verification/characters/tools/key_*.py` が直接WebPで出す）。PNGは残さない（name-name のTUIは WebP のみデコードできる）。実寸（不変）・アルファ（`magick in.png -alpha extract` と変換後WebPの同コマンドを `compare -metric AE` で比べAE=0）の検査はWebPで行う。寸法ゲートの基準（1920×1080等）は変えない。

失敗の来歴（完全prompt・参照・実寸/検査結果・判定理由）はIssueまたはレビュー文書に記録し、失敗画像はリバートする（バイナリを別置き場に保存しない）。

劇・屋外を含む戦闘用背景を扱う。旧BG005は没・削除（2026-10-21、git `19ab92a`。素材A-038）。劇背景の正本は未定なので、決まるまで生成を停止する。没画像を参照にしない。通常のフィールド背景は `sit-field-background` を使う。

## 一意解釈ゲート（このスキルの全行より優先）

生成入力・検査には、参照画像パス、1920×1080座標、画面端、ピクセル数、個数、材料名、色名、または下記で定義した方向だけを使う。`少し`、`やや`、`広い`、`狭い`、`近い`、`遠い`、`自然`、`十分`、`明瞭`、`目立つ`、`適切`、`雰囲気`、`おおよそ`、`〜風`、`斜め`だけ、`奥行き`だけは実行語として禁止する。必要な条件をそれらだけで表している場合、座標・参照画像・数値へ変換できるまで生成を停止する。背景と地面の境界は、左端のy座標から右端のy座標を**40 logical pixels以上小さくする**場合だけ「左下から右上」と判定する。

床板、幕、書き割りを、見栄えのために直線・直交・等間隔・格子へ正規化してはならない。形・数・位置は参照画像または原文にあるものだけを使う。

## エリア固定と戦闘背景（kako-jun 2026-10-30、決定 BTL.bg-same-area-fixed-closer-shallower）

**戦闘背景＝マップと同じエリア固定＋より寄り・見下ろし角が浅い。** 机の天面・台座・木・外周は台帳 `docs/ledger/エリア固定.yaml`（エリア表の4列、決定 `<区域コード>.area-fixed`／寺町は `TRM.desk`・`TRM.trees-pine`）を正とし、戦闘の場所のエリアのものをそのまま使う（寺町なら温かい茶色の板張りの机〔板目は横〕・段ボール＋綿の雪の台座・松と枯木が、戦闘背景にも同じに載る）。エリア固定が未決の項目（例: 金沢駅の木）は生成を止める。マップとの違いはカメラだけ: 構図がもっと寄る・見下ろし角が浅い。寄りの倍率・俯角の数値は未決（U-2912）で、BG001.webp と下の右端y規則を正とし、数値を発明しない。

**混同防止**: `sit-field-background` の斜めモック（oblique 系。真上寄りの見下ろし約42度・モック座標・COORDINATES）は戦闘背景に流用しない。戦闘背景のカメラは上の規則と BG001.webp から取る。なお、戦闘背景のプロンプトを台帳から組む経路は現状無い（戦闘背景用の表も無い）ため、エリア固定は生成入力へ手で渡す（台帳の値を逐語で）。

## ミニチュア材料・道具の固定宣言

下の材料は**劇の背景**の指定。屋外・エリアの背景の机・台座・木は上のエリア固定が優先する。劇の背景では「手作り舞台」「ミニチュア」だけで生成せず、床=`balsa wood` または `popsicle sticks` をクラフトナイフで切断、書き割り=`corrugated cardboard` と `matte poster paint`、幕=`felt` または `tissue paper`、固定=`masking tape`・PVA接着剤、土台=`foamboard` と露出段ボール断面を対象ごとに指定する。屋外背景は対応MAP原文と `sit-field-background` の対象別材料・加工法を使い、劇場床・幕・書き割りを追加しない。実物素材やCG均一面で代替しない。指定した材料・切断面・テープ・接着剤・土台断面のうち三つ以上を原寸の証拠座標で確認できなければ `failed` として記録し、採用候補へ進めない。

開始前に `docs/content-registry.md` から対象の戦闘・MAP IDを確定し、対象MAPの原文、`docs/art-direction.md`、対応する戦闘レイアウトJSONのキャラ・敵・UIの安全領域を読む。 対戦相手の敵IDまたは召喚獣IDが確定している場合は `uv run python3 scripts/content_ledger.py query enemy Mxxx --gate` または `query summon Sxxx --gate` を実行し、配置・戦闘パターン案・適用決定を生成入力へ渡す。ゲート失敗ならその対象の生成を止める。劇の場合は `docs/roadmap.md` の劇背景決定も読む。

## 絶対ゲート: 参照MAPと戦闘面の角度

生成前に、戦闘の場所に対応するフィールドMAPを原文台帳から確定し、**実際のMAP画像を imagegen の参照画像として必ず入力する。** 劇なら該当する幼稚園／遊戯室MAPを両方確認し、屋外なら該当する屋外MAPを全て確認する。どの画像を建築・材料・幕・室内位置関係・地面のどれの根拠に使うかを生成記録に残す。文章だけで場所を再現してはならない。対応MAPが無い、原文と画像が矛盾する、または参照画像を入力できない場合は生成を停止する。

`assets/images/battle-backgrounds/BG001.webp`（旧bg-a）をカメラ参照画像として入力する。旧BG005は没なので使わない。地面と背景の接する線について、右端のy座標を左端のy座標より40 logical pixels以上小さくする。真上見下ろし、正面カメラ、水平な地面・背景境界を出力しない。

**反復する床板線・轍・溝・タイル線は必須ではない。** それらは場所の原文またはユーザーが要求した場合だけ描く。角度の根拠を線の反復で代用してはならない。

生成後、原寸で次の全項目を二択確認する。ひとつでも `いいえ` なら `failed` として記録し、採用候補・後工程へ進めない。

1. 対応フィールドMAPを実際に参照画像として渡したか。
2. 地面と背景の接する奥端が、左下から右上へ上がる画面方向になっているか（右端が左端より明確に高いか）。
3. 地面の角度を、不要な反復線の追加で偽装していないか。
4. 参照MAPの建築・材料・場所の手がかりと矛盾していないか。

## 背景契約

- 横長16:9（1920×1080論理座標）にする。人物、読める文字、ロゴ、透かしは入れない。
- 味方、敵、十字コマンド、メッセージ窓の占有矩形は対象戦闘のレイアウトJSONの値をそのまま読み、その矩形に背景物を置かない。
- 劇の背景は正本が決まるまで生成を停止する。旧BG005の幕・書き割り・舞台床は履歴であり、新しい採用の根拠にはしない。
- 屋外を対象にするときは、建築・地面・天候・時刻を対応MAP原文と参照MAP画像からだけ取る。劇の幕、書き割り、舞台床を追加しない。

## 運用

生成前に完全prompt、対応MAP原文、実参照画像と用途、安全矩形の出典を `sit-artifact-redteam` のpromptレビューへ渡す。旧候補と現行契約の矛盾を隠して建築の根拠にしない。利用可能な `imagegen` スキルと組み込み `image_gen` を使う。実ファイルが1920×1080か測定し、原寸上の境界両端座標と材料の証拠座標を記録する。論理座標や16:9比率だけでは寸法を証明できない。完全prompt・参照・測定値・結果を記録し、独立生画像レビュー後に実戦闘へ重ねる。保存禁止は採用候補化の禁止を意味し、失敗来歴を捨てる指示ではない。

1. 戦闘背景IDは#68の対応台帳で確定し、正本を `assets/images/battle-backgrounds/BGxxx.webp`へ直接上書き保存する（`candidates/` や版suffixは使わない）。合格ならコミット、不合格・不採用は `git restore <path>`（未追跡の新規ファイルは即削除）でリバートし、不採用・失敗画像は置き場に残さない。**使う可能性のあるテイクは、次を生成する前にコミットする**（未コミットの新規ファイルは次の上書きで消える）。`git add` は名指し。採用状態は置き場でなく台帳のstatusで管理する。 上書きで既存の採用画像を置き換える場合は、現行をコミット済みか先に確認する。
2. 生成後、16:9比率、アクスタ／敵／UIの余白、幕・書き割りの舞台性、文字なしを確認する。
3. 実際の戦闘画面に重ね、ライブ表示で視認性を確認してから採用を判断する。

共通（#68運用）: 合格済みの正本を上書きする前に、現行がコミット済みか確認する。不合格テイクをコミット済みにしてしまった場合は `git revert <commit>`、または `git checkout <旧commit> -- <path>` で戻す。
