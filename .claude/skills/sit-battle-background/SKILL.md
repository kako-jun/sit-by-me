# Sit by Me 戦闘背景

**画像の保存形式（#68決定、2026-10-19）**: imagegenの出力（PNG）→切り出し→**WebP（非可逆・品質85・アルファ保持）**にして正本パスへ保存する（`magick in.png -quality 85 out.webp`、または `verification/characters/tools/key_*.py` が直接WebPで出す）。PNGは残さない（name-name のTUIは WebP のみデコードできる）。実寸（不変）・アルファ（`magick in.png -alpha extract` と変換後WebPの同コマンドを `compare -metric AE` で比べAE=0）の検査はWebPで行う。寸法ゲートの基準（1920×1080等）は変えない。

失敗の来歴（完全prompt・参照・実寸/検査結果・判定理由）はIssueまたはレビュー文書に記録し、失敗画像はリバートする（バイナリを別置き場に保存しない）。

劇・屋外を含む戦闘用背景を扱う。台帳は `docs/ledger/戦闘背景.yaml`（BG011=お遊戯会の舞台〔使う戦闘 opening_battle〕、BG012=寺町の道路〔寺町の特徴だけを合わせた、どのマップとも一致しない景色〕。決定 BTL.bg011-bg012-staff-judgment〔2026-11-11 訂正〕、Issue #267）。**戦闘背景はイメージであり、実マップの再現ではない**（kako-jun「戦闘画面はあくまでイメージなのだから、実際のマップと完全一致する必要はない」）。旧BG005は没・削除（2026-10-21、git `19ab92a`。素材A-038）。没画像を参照にしない。通常のフィールド背景は `sit-field-background` を使う。

## 一意解釈ゲート（このスキルの全行より優先）

生成入力・検査には、参照画像パス、1920×1080座標、画面端、ピクセル数、個数、材料名、色名、または下記で定義した方向だけを使う。`少し`、`やや`、`広い`、`狭い`、`近い`、`遠い`、`自然`、`十分`、`明瞭`、`目立つ`、`適切`、`雰囲気`、`おおよそ`、`〜風`、`斜め`だけ、`奥行き`だけは実行語として禁止する。必要な条件をそれらだけで表している場合、座標・参照画像・数値へ変換できるまで生成を停止する。背景と地面の境界は、左端のy座標から右端のy座標を**40 logical pixels以上小さくする**場合だけ「左下から右上」と判定する。

床板、幕、書き割りを、見栄えのために直線・直交・等間隔・格子へ正規化してはならない。形・数・位置は参照画像または原文にあるものだけを使う。

## エリア固定と戦闘背景（kako-jun 2026-10-30、決定 BTL.bg-same-area-fixed-closer-shallower）

**戦闘背景＝マップと同じエリア固定＋より寄り・見下ろし角が浅い。** 机の天面・台座・木・外周は台帳 `docs/ledger/エリア固定.yaml`（エリア表の4列、決定 `<区域コード>.area-fixed`／寺町は `TRM.desk`・`TRM.trees-pine`）を正とし、戦闘の場所のエリアのものをそのまま使う（寺町なら温かい茶色の板張りの机〔板目は横〕・段ボール＋綿の雪の台座・松と枯木が、戦闘背景にも同じに載る）。エリア固定が未決の項目（現在は奥能登への鉄道の木だけ。車内のみで外の景色が無い）は生成を止める。金沢駅の木は松（kako-jun 指示「金沢駅の木は松だ」、決定 STN.area-fixed）、K空港の木は松（小松空港の空港前に松がある、APT.area-fixed）、小学校の木は山の木（小木小学校の周囲の山の木。樹種は特定しない、SCH.area-fixed）で確定済みなので、ラストバトルの戦闘背景も木で止まらない。マップとの違いはカメラだけ: 構図がもっと寄る・見下ろし角が浅い。寄りの倍率・俯角の数値は未決（U-2912）で、BG001 の比率（没の立体は参考にしない）と下の右端y規則を正とし、数値を発明しない。

**混同防止**: `sit-field-background` の斜めモック（oblique 系。真上寄りの見下ろし約42度・モック座標・COORDINATES）は戦闘背景に流用しない。戦闘背景のカメラは上の規則と BG001 の比率（実測値）から取る。なお、劇の背景（BG011）の送信文は `tools/battle_bg_build.py` が台帳（戦闘背景.配置・プロンプト文面 PR.battle.*）から機械生成する（下の「生成の手順（スキルだけで行う）」）。

## ミニチュア材料・道具の固定宣言

下の材料は**劇の背景**の指定。屋外・エリアの背景の机・台座・木は上のエリア固定が優先する。劇の背景では「手作り舞台」「ミニチュア」だけで生成せず、床=`balsa wood` または `popsicle sticks` をクラフトナイフで切断、書き割り=`corrugated cardboard` と `matte poster paint`、幕=`felt` または `tissue paper`、固定=`masking tape`・PVA接着剤、土台=`foamboard` と露出段ボール断面を対象ごとに指定する。屋外背景は対応MAP原文と `sit-field-background` の対象別材料・加工法を使い、劇場床・幕・書き割りを追加しない。実物素材やCG均一面で代替しない。指定した材料・切断面・テープ・接着剤・土台断面のうち三つ以上を原寸の証拠座標で確認できなければ `failed` として記録し、採用候補へ進めない。

開始前に `docs/content-registry.md` から対象の戦闘を確定し、参照する採用済みの絵の元MAPの原文（材料の根拠）、`docs/art-direction.md`、対応する戦闘レイアウトJSONのキャラ・敵・UIの安全領域を読む。 対戦相手の敵IDまたは召喚獣IDが確定している場合は `uv run python3 scripts/content_ledger.py query enemy Mxxx --gate` または `query summon Sxxx --gate` を実行し、配置・戦闘パターン案・適用決定を生成入力へ渡す。ゲート失敗ならその対象の生成を止める。劇の場合は `docs/roadmap.md` の劇背景決定も読む。

## 絶対ゲート: 参照見本と戦闘面の角度

生成前に、**採用済みのフィールド絵（BG011=TRM-02 の舞台の部分、BG012=寺町の採用済み絵の素材・様式）から切り出した見本を imagegen の参照画像として入力する**（2026-11-11 訂正。MAP 全体や構図は渡さない）。どの見本を材料・幕・書き割り・雪・土塀などのどれの根拠に使うかを生成記録に残す。文章だけで素材を再現してはならない。見本が作れない、原文と画像が矛盾する、または参照画像を入力できない場合は生成を停止する。

`assets/images/battle-backgrounds/BG001.webp`（旧bg-a）は没（比率はよいが立体が不自然。決定 BG001.rejected-provisional-keep）なので、カメラ参照画像として入力せず、立体の参考にしない。参考にするのは比率だけ（BG001 の実寸 1672×941 の座標系で、地面は高さの約8割・境界は右上がり、左端 y=290・右端 y=115 の実測値。これは参考の実測値であり、出力への実行語ではない。実行する規則は下の「右端のy座標を左端より40 logical pixels以上小さくする」だけ）。旧BG005も没なので使わない。地面と背景の接する線について、右端のy座標を左端のy座標より40 logical pixels以上小さくする。真上見下ろし、正面カメラ、水平な地面・背景境界を出力しない。

**反復する床板線・轍・溝・タイル線は必須ではない。** それらは場所の原文またはユーザーが要求した場合だけ描く。角度の根拠を線の反復で代用してはならない。

生成後、原寸で次の全項目を二択確認する。ひとつでも `いいえ` なら `failed` として記録し、採用候補・後工程へ進めない。

1. 採用済みの絵から切り出した見本を、参照画像として実際に渡したか（MAP 全体・構図は渡していないか）。
2. 地面と背景の接する奥端が、左下から右上へ上がる画面方向になっているか（右端が左端より明確に高いか）。
3. 地面の角度を、不要な反復線の追加で偽装していないか。
4. 参照見本の材料・様式、および原文の場所の手がかり（舞台・寺町の特徴）と矛盾していないか。

## 背景契約

- 横長16:9（1920×1080論理座標）にする。人物、読める文字、ロゴ、透かしは入れない。
- 味方、敵、十字コマンド、メッセージ窓の占有矩形は対象戦闘のレイアウトJSONの値をそのまま読み、その矩形に背景物を置かない。
- **劇の背景（BG011）は舞台の上そのもの**。書き割りの城と山・緞帳・舞台の板張りの床・足元の灯り・舞台袖の緞帳だけ。遊戯室の床・壁・おもちゃ棚・テーブル・椅子は入れない。参照画像は採用済み TRM-02（`assets/images/fields/reference/teramachi-kindergarten-playroom-trm02-adopted.webp`）の**舞台の部分の切り出し**（書き割り・緞帳・舞台の板が写る範囲）で、素材感の見本。TRM-02 の構図（舞台が奥にあり手前に部屋）をコピーさせない。
- **舞台の絵は『実マップの舞台（採用済み TRM-02）どおり』**＝TRM-02 の舞台部分に写っている書き割り・緞帳・柱・舞台板の材料・色・モチーフに揃え、写っていない物は足さない（kako-jun 2026-11-12「舞台の絵がマップと違いすぎる」）。具体物は台帳 BG011 のカメラ欄。
- **カメラ**: ジオラマを舞台の正面でなく少し斜め左の位置から浅い角度で見下ろす（kako-jun 2026-11-12。角度の数値は未決 U-2912、発明しない）。板に貼り付けた平面にしない。
- 劇の構図: 舞台の上に敵（左）・味方（右）が立てる広さの舞台面を画面中ほどに置く（物の位置は『配置』列）。旧BG005の幕・書き割り・舞台床は履歴であり、採用の根拠にしない。
- **寺町の屋外の背景（BG012）は、特定のMAPの再現ではなく、寺町の特徴だけを合わせた、どのマップとも一致しない景色**（2026-11-11 kako-jun）。特徴=古い土塀と戸室石の基礎、寺の瓦屋根、雪囲い、消雪パイプの穴の並ぶ道（中央線上の穴だけ・水の噴射なし）、道の脇の側溝・縁石・段差、綿の雪。参照は特定の1枚に固定せず、採用済みの寺町の絵から素材・様式の見本として切り出した見本シートを渡す。TRM-07 の作り直しを待たない。劇の幕、書き割り、舞台床は追加しない。
- **戦闘UIの安全矩形・床の四隅・各物の位置は台帳 `戦闘背景.yaml` の『配置』列が正本**（数値をこの文書へ書かない。安全矩形は name-name の `computeSideBattleLayout` を 1672×941・味方4人・敵1体・敵名窓ありで実測した値。画面サイズ・人数・敵の数が変わる戦闘では、同関数で測り直して台帳を直す）。物（城・樅・緞帳・柱・ランタン）は安全矩形に置かない。

## 無駄な生成を防ぐ手順（kako-jun 2026-11-11「無駄な生成をするな」。BG011 の4枚が構図の誤りで全没になった）

生成の前に、次を**チェックリストで全部確認し、記録する**。ひとつでも空なら生成しない。
1. 構図: 何を描くか（戦う場所そのもの）と、描かないもの（実マップの部屋・床・壁など）を、kako-jun の逐語で確かめた。
2. 参照: 渡す見本（採用済みの絵からの切り出し）と、各見本の用途。構図コピーが起きない切り出しか。
3. prompt: 完全な送信文。禁止語を書いていない（肯定形）。一意解釈ゲートの実行語禁止を満たす。
4. 素材感: `SIT.miniature-materials-not-photoreal` の確立された方法（別担当の実験結論=参照見本シート・prompt の構成。記録の置き場は Issue #267 のコメント。結論が出るまでは未取り込みなので生成しない）を取り込んだ。`sit-field-background/pitfalls.md` の G 節のチェックリストも通した。
5. 安全矩形: 上の実測値。背景物が矩形に被らない設計か。

そのうえで `sit-artifact-redteam` の生成前の独立レビューを受け、blocker・major を0にする。**最初は最小の1枚だけ生成し、kako-jun に見せて承認を得てから**追加のテイクを作る（4枚の一括生成は禁止）。承認前の再生成・並行生成もしない。

## 生成の手順（スキルだけで行う。kako-jun 2026-11-12「画像作成はぜんぶスキル以外ではするな」）

手で送信文を書かない・手で割付図を描かない・場当たりの合成をしない。足りない所があれば、生成の前にこのスキル（SKILL.md・tools・台帳）を直す。

1. 参照見本: `magick assets/images/fields/reference/teramachi-kindergarten-playroom-trm02-adopted.webp -crop 480x260+600+150 +repage <作業>/stage-ref.png`（TRM-02 の舞台部分。材料・色・モチーフだけの見本）。
2. `uv run --with pillow --with numpy python3 -I .claude/skills/sit-battle-background/tools/battle_bg_build.py build BG011 --stage-ref <作業>/stage-ref.png --out <作業>/` → 生成前の検査（物が安全矩形に重ならない・床の奥の縁が右上がり）に通れば `layout.png`（割付図・clean）・`send.txt`・`refs.txt` が出る。落ちたら生成せず台帳の『配置』を直す。
3. `codex exec -s workspace-write --skip-git-repo-check -i <layout.png> -i <stage-ref.png> < send.txt` を1回だけ（参照は割付図→見本の順。リトライなし）。出力は codex.log の `session id:` と一致するセッション配下から無加工で回収する。
4. `... battle_bg_build.py check BG011 <画像> --out <作業>/` → 実寸・安全矩形の重ね画像 `overlay.png`・城の赤い屋根の位置を検査（城が枠の外／矩形に重なれば NG）。樅・緞帳・柱・ランタン・前縁（無地）・奥の縁の右上がり・ミニチュア感は `overlay.png` を目視して適合表にする。
5. 城などが座標を守れず NG の時: 同じ送信文の再生成は繰り返さない。`battle_bg_build.py mask BG011 castle --out <mask>` で城の枠のマスクを作り、`image-local-replace` スキル（マスク内だけ直し、マスク外は画素同一を検証）で城だけ局所合成する。割付図・マスクは台帳『配置』から機械生成したものだけを使う。
6. `tools/battle_base.py` は旧来の平行投影（俯角65度）の下絵ツールで、BG011 の手順では使わない（U-2912 の数値未決のため）。

## 運用

生成前に完全prompt、対応MAP原文、実参照画像と用途、安全矩形の出典を `sit-artifact-redteam` のpromptレビューへ渡す。旧候補と現行契約の矛盾を隠して建築の根拠にしない。利用可能な `imagegen` スキルと組み込み `image_gen` を使う。実ファイルが1920×1080か測定し、原寸上の境界両端座標と材料の証拠座標を記録する。論理座標や16:9比率だけでは寸法を証明できない。完全prompt・参照・測定値・結果を記録し、独立生画像レビュー後に実戦闘へ重ねる。保存禁止は採用候補化の禁止を意味し、失敗来歴を捨てる指示ではない。

1. 戦闘背景IDは `docs/ledger/戦闘背景.yaml` で確定し、正本を `assets/images/battle-backgrounds/BGxxx.webp`へ直接上書き保存する（`candidates/` や版suffixは使わない）。合格ならコミット、不合格・不採用は `git restore <path>`（未追跡の新規ファイルは即削除）でリバートし、不採用・失敗画像は置き場に残さない。**使う可能性のあるテイクは、次を生成する前にコミットする**（未コミットの新規ファイルは次の上書きで消える）。`git add` は名指し。採用状態は置き場でなく台帳のstatusで管理する。 上書きで既存の採用画像を置き換える場合は、現行をコミット済みか先に確認する。
2. 生成後、16:9比率、アクスタ／敵／UIの余白、幕・書き割りの舞台性、文字なしを確認する。
3. 実際の戦闘画面に重ね、ライブ表示で視認性を確認してから採用を判断する。

共通（#68運用）: 合格済みの正本を上書きする前に、現行がコミット済みか確認する。不合格テイクをコミット済みにしてしまった場合は `git revert <commit>`、または `git checkout <旧commit> -- <path>` で戻す。

## 採用後の台帳・デモ配線（BG011 など劇の背景）

採用したら `戦闘背景.yaml` の状態・画像パス・配信用複製を埋め、素材.yaml に登録し、配信用複製を `assets/images/fields/play/` に作る（1MiB 以下。手順は ファイル配置.yaml の field-play-background）。`docs/ledger/イベント/opening_battle.yaml` の `戦闘背景` 列に配信用複製のパス（`fields/play/…`）を入れて `uv run python3 scripts/build_ledger.py build` する（`scripts/field_md.py` が `[フィールドマップ … 戦闘背景=…]` を出す）。BG011 の採用後に BG001 を素材・台帳から削除する。
