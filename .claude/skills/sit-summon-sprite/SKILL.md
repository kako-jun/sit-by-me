# Sit by Me 召喚獣スプライト

失敗の来歴（完全prompt・参照・実寸/検査結果・判定理由）はIssueまたはレビュー文書に記録し、失敗画像はリバート／削除する（バイナリを別置き場に保存しない）。

召喚獣 `S` の戦闘用マスター画像だけを扱う。生成前に `docs/content-registry.md`、`docs/monsters.md` の対象行、`docs/story.md` の対象行、`docs/art-direction.md`、`docs/assets-policy.md` を原文のまま読む。対象行が `ready` でない、TBDが残る、または敵起源の対応IDが欠ける場合は生成しない。

## 一意解釈ゲート

生成入力・検査には、召喚獣ID、台帳原文、参照画像パス、キャンバスpx、グリッド種別、画面座標、色コード、個数、材料名、定義済み角度だけを使う。台帳にない姿、場所、属性、武器、人物を補完しない。

## 向き・グリッド・透明条件

召喚獣は対応する敵マスターと同じ規則で作る。頭部・胴体はカメラ正面 `0°` から `+x` 側へ `45°` のヨー角にし、真右 `90°` の横顔だけを禁止する。瞳の視線だけは `+x` でよい。右側に召喚される表示ではレンダラーが左右反転するため、文字、ロゴ、左右で意味が変わる記号を入れない。台座、輪郭線、接地影も入れない。

`gridClass` は `1x1`、`2x1`、`1x2`、`2x2` の4種だけである。台帳行の値をそのまま使う。キャンバスは順に 1024×1024、2048×1024、1024×2048、2048×2048 px とし、透明でない外接矩形は幅・高さとも各辺の92–96%に収める。召喚獣のグリッド種別を名前や見た目から推測しない。

## 生成・検査

生成前に完全prompt・台帳原文・参照画像と用途を `sit-artifact-redteam` のpromptレビューへ渡す。利用可能な `imagegen` スキルと組み込み `image_gen` を使い、透過をツール設定でも要求する。実寸、alpha=0画素の存在、alpha>0の最小外接矩形 `(x,y,width,height)` と幅/高さ比率を測定して保存する。RGBA形式名・prompt指定だけでは透過や寸法を証明できない。頭部・胴体の正面面と右側面を個別に確認する。失敗は完全prompt・参照一覧・測定値・判定をIssueまたはレビュー文書に `failed` として記録し、画像はリバートして次工程へ渡さない。自動再生成や引伸ばしで通過させない。

透過背景で1候補だけ生成し、正本 `assets/images/summons/Sxxx.png` へ直接上書き保存する。保存は直接上書き: 生成物はサンプル・候補の置き場に置かず、ゲームで使う正本パスへ直接上書きする（#68決定、2026-10-19）。合格ならコミット、不合格・不採用は `git restore <path>`（未追跡の新規ファイルは即削除）でリバートし、不採用・失敗画像は置き場に残さない。**使う可能性のあるテイクは、次を生成する前にコミットする**（未コミットの新規ファイルは次の上書きで消える）。`git add` は名指し。採用状態は置き場でなく台帳のstatusで管理する。 加工前の原本（`raw/`）は保管しない（#68決定、2026-10-19）。S番号は召喚獣台帳を正本にし、S008など画像が存在しない欠番を補作しない。原寸で、台帳原文との一致、45°の頭部・胴体、4種のいずれかの`gridClass`、指定キャンバス、外接矩形92–96%、文字・ロゴ・台座・接地影なしを確認する。採用前に `sit-artifact-redteam` の独立レビューへ渡す。

共通（#68運用）: 合格済みの正本を上書きする前に、現行がコミット済みか確認する。不合格テイクをコミット済みにしてしまった場合は `git revert <commit>`、または `git checkout <旧commit> -- <path>` で戻す。
