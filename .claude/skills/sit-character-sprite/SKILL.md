**画像の保存形式（#68決定、2026-10-19）**: imagegenの出力（PNG）→切り出し→**WebP（非可逆・品質85・アルファ保持）**にして正本パスへ保存する（`magick in.png -quality 85 out.webp`、または `verification/characters/tools/key_*.py` が直接WebPで出す）。PNGは残さない（name-name のTUIは WebP のみデコードできる）。実寸（不変）・アルファ（`magick in.png -alpha extract` と変換後WebPの同コマンドを `compare -metric AE` で比べAE=0）の検査はWebPで行う。寸法ゲートの基準（1920×1080等）は変えない。

Sit by Me の4人（と子供3人、不良など人物）の絵を、生成 → 確認 → 透過・切り出し → 保存 → 記録の順で作る。敵は `sit-enemy-sprite`、召喚獣は `sit-summon-sprite`、フィールド背景は `sit-field-background`、戦闘背景は `sit-battle-background`。ここは人物スプライトだけ。

## 一意解釈ゲート（このスキルの全行より優先）

人物生成の条件には、参照画像パス、人物ID、年齢段階、衣装名、向き、ポーズ名、コマ数、画像寸法、色名、または原文にある固有名だけを使う。`少し`、`やや`、`自然`、`十分`、`明瞭`、`目立つ`、`適切`、`雰囲気`、`おおよそ`、`〜風`は生成条件として禁止する。これらの語を眉・目・口・手・足・衣装・向き・座標・色へ変換できなければ生成しない。

## 曖昧なミニチュア指定の禁止

人物素材はミニチュア背景ではない。人物に「模型風」「手作り風」を追加してはならない。人物を背景へ合成する依頼でミニチュア材料の指定が必要な場合は、このスキルで補完せず、背景側の `sit-field-background` または `sit-battle-background` の材料・道具宣言を正本にする。

先に `docs/art-direction.md`（人物素材・4人の呼称と特徴）と `docs/assets-policy.md`（マスターの一覧・命名）と `docs/decisions.md` を読み、何がすでに決まっているかを確かめる。サンプル用ではなく、設定が正本。

別のゲームのスプライトを作るときは、このスキルをそのまま使わない。ツール（`verification/characters/tools/`）と手順の考え方を流用し、そのゲームの設定を正本にする。

## 0. 原則

失敗の来歴（完全prompt・参照・実寸/検査結果・判定理由）はIssueまたはレビュー文書に記録し、失敗画像はリバート／削除する（バイナリを別置き場に保存しない）。

- **生成ごとに会話へ貼る**（SendUserFile。URL だけ・まとめ見せ・選別は不可）。縮小した一覧で確認してよいのは自分の検品用だけで、kako-jun には元画像を送る
- **やることは生成前に Issue に書く**。決定（kako-jun の指示）は docs と Issue に即記録する
- **作業用の画像はスクラッチに置き、採用したらすぐリポへコミットする**。スクラッチはセッション再開で消える（2026-10-14 実害）。消えたら `~/.codex/generated_images/` から時刻と寸法で回収できる
- 生成はまず対象1件ずつ検査する。複数案や並列生成は依頼された範囲に限定する。
- 創造的な選択（案 a/b、色、意匠）は kako-jun が決める。任されたら推しを理由つきで出して進める
- 複数案が依頼された場合だけ案を並べる。採用済みの絵は指摘点だけを直す。
- **年齢・制服・地域・設定の社会的な決まりは推測で決めない**。決定は docs/decisions.md にある。ない点は聞く（2026-10-14: 小学校にセーラー服はない、北陸は小学生も制服、など推測の誤りが出た）

## 1. 生成の呼び出し

利用可能な `imagegen` スキルを読み、組み込み `image_gen` で生成・編集する。参照は実画像で渡し、identity／layout／edit target の用途を明示する。ツールに無いモデル・quality・size引数や古い `codex exec` 呼出しを必須にしない。利用不能ならコードで代作せず原因を記録する。

### 部分編集・縮小表示の再現性ゲート（2026-10-26）

- 「この部位だけ変える」「他の画素を完全に保つ」「手を座標 `(x,y)` へ置く」など、厳密な変更範囲や位置が明示的な合否条件なら、生成編集の限界をIssueに記録し、可能ならマスク合成を使う。数値はユーザーが厳密さを求めていない限り、位置合わせの目安として扱う。
- 多くのスプライトはゲーム中に縮小表示される。原寸の機械差分やalphaの微小ノイズだけで不採用にせず、実際の表示寸法と白/暗色背景で見て、歩行位相・接地・接触・輪郭・同一性が読めるかを優先する。縮小後に見えない微小な色片・1px差は、それ単独では不合格にしない。
- 画像を切り出し・配置するときは縦横比を保ち、出力キャンバスと足元位置をプロジェクトの既存セットに合わせる。`-resize WxH!` の非等方拡大縮小で人物・車椅子の比率を調整しない。許容寸法や人物スケールは、対象キャラの同方向・同時期の採用画像と一覧で比較する。
- alpha min/max は透明値の存在確認にすぎない。alpha bbox・基線・対象寸法を測り、白/暗色合成でノイズの位置も確認するが、機械検査は目視の補助として使う。背景片やフリンジが最終表示でも見える、接地が崩れる、位相が読めない場合は `failed`。
- 失敗候補を同じ方式のまま言い換えて繰り返さない。再試行を依頼された場合は、失敗原因をIssueへ記録し、方式または参照を変える理由と最終表示での検査方法を更新してから新しい1候補を作る。

生成前に完全prompt・設定原文・参照一覧を独立promptレビューへ渡す。まず1候補を生成し、原本・完全prompt・参照・寸法・結果を記録する。`file` 等で実寸を測り、透過素材はalpha=0画素の存在も検査する。RGBA形式名だけで透過と判定しない。原寸で顔・衣装・向き・全コマ・縁を目視し、切り出し後も独立画像レビューを通す。失敗は判定・prompt・測定値をIssueまたはレビュー文書に `failed` と記録して画像はリバートし、自動再生成しない。保存は正本パスへの直接上書きで、合格ならコミット、不合格は git でリバートする。**使う可能性のあるテイクは次を生成する前にコミットする**（未コミットの新規ファイルは上書きで消える）。採用状態は置き場でなく台帳・Issueのstatusで管理する。

## 2. マスター三面図（同一性の基準）

- 1枚に **正面・横・背面の全身**、暗いグレーの無地背景、1536x1024
- 以後の生成はすべてこのマスターを参照する。マスターが決まるまでポーズを量産しない
- 顔立ちは人種・年齢を明記する（日本人の顔立ち、一重、垂れ目など。4人の特徴は art-direction）。金髪の全面指定は白人顔に寄るので、メッシュなど部分で入れる
- AI の定番顔・テンプレ服にしない。キャラごとの特徴（髪の一部の色、眼鏡、マフラー、大きな帽子など）を入れる

## 3. 服だけ・部分だけ変える（編集）

- 既存のマスターを **編集元** にし、「Change ONLY …／Keep EVERYTHING ELSE identical」で変える部分を1点に絞る（服を園服に、鞄を外す、靴を上履きに、スパッツを外す、帽子を大きく、マフラーを足す）
- 顔・髪・帽子・構図を保ったまま衣装差分が作れる。新規生成より同一性が高い
- 1回の編集で変えるのは1〜2点まで

## 4. 年齢段階

- 前の段階の採用画像を参照して、**1段ずつ** 歳をとらせる（幼稚園 → 小学生 → 中高生 → 青年 → 壮年）。幼稚園から大人へ一気に飛ばすと顔が子供のまま残る
- 「顔と体がその年齢に明確に見えること（大人の骨格、子供の丸みなし）」を書く。若く出たら顔だけ編集で直す
- 年齢ごとに服と帽子のデザインを変える。髪の色・特徴は引き継ぐ。服の色は大人ほど落ち着かせ、髪は派手なまま（decisions）
- 壮年編に出るのは主人公・配偶者・子供3人。友達2人は離脱するので壮年版は要らない

## 5. 車椅子版

- 立ち姿のマスターを編集元にし、同じ三面で車椅子に座らせる
- **切断面は描かない**。膝掛け・コートで太ももから膝を覆い、片足だけ出す。素の切断描写は出力モデレーションで約半数が拒否される
- 「fully clothed」「wheelchair user」「dignified everyday look」と書く
- 戦闘もフィールドも車椅子のまま（立たせない）。戦闘ポーズは立ちのグリッドを配置の参照にして「seated in the wheelchair in every cell」と書き、9 ポーズを読み替える（突進=ハンドリムを強くこぐ、必殺技=前輪を上げた突進、など）

## 6. 戦闘ポーズ（3x3 グリッド）

- 9 ポーズを **1枚の 3x3 グリッド** で生成する（同時に作ると同一性が保てる）。並び: 待機 / 構え / 踏み込み / 斬る / 被ダメージ / 倒れ / 詠唱 / 必殺技 / 勝利（決めポーズ。年齢をまたいで同じ）
- 3x3の各セルに全身を収め、隣の人物と重ねない。車椅子・帽子・手・小道具もセル境界を越えず、人物の間に透明な間隔を残す。収まらない場合は縦横比を保って人物全体を一様に縮小する。ゲーム内で縮小表示する素材では、各セルをぎりぎりまで埋めず、人物とポーズの識別を優先する（C001中学生車椅子の2026-10-26生成で、行境界の重なりが1コマ欠落と隣コマへの帽子混入を起こしたため）。
- `key_grid.py` が `EMPTY` を返す、隣の人物の断片が切り出しへ入る、または手足・車輪がセル端で切れる場合は、その候補を手作業の境界切りで採用しない。原因をIssueへ記録し、セル内の余白を増やすpromptへ変えて再生成する。見えない微小ノイズと、ポーズやシルエットが損なわれる重なりは別の合否として扱う。
- **刀・武器は人物と別レイヤーで再利用する（kako-jun 2026-10-26）**。同じ刀を年齢・衣装・車椅子ごとに描き直さず、刀ごとに共通画像を1枚作り、`ready / slash / special` など攻撃ポーズごとの大まかな位置・縮尺・角度を複数世代へ適用する。刀は人物の前面へ表示する。表示時間が短く、縮小されるため、指と柄の完全な接触や遮蔽は合否条件にせず、拳の近くに柄があり攻撃姿勢として読めるかを確認する。共通transformが立位と車椅子など異なるポーズ構造で明らかに崩れる場合だけ、構造別に少数のtransformへ分け、年齢ごとの武器画像を増やさない。位置合わせは透明余白を除いた人物の可視bboxを基準にし、立位・車椅子など拳の位置が構造的に異なる場合は位置transformだけ分ける。刀画像は同じものを使い、各構造から1セット以上を縮小合成して確認する（C001 2026-10-26: 小学生立位＋壮年車椅子の比較で構造別位置を確認）。
- 武器レイヤーを使うゲームアニメーションでは、キー姿勢を先に確認し、後続工程で振り始め・振り抜きなど隣り合うポーズを補う中間ポーズを作って滑らかにつなぐ。最初から全組み合わせの画像を作らず、共通武器レイヤーと少数の姿勢・transformで成立するかを縮小表示で確かめる。
- C001の通常斬撃では `ready → swing-windup → slash → swing-followthrough → ready` を基本列にする。各年齢・立位/車椅子セットの人物単体 `ready` と `slash` を参照画像として、新規にwindup/followthroughを作る。左セル=windup、右セル=followthroughの1×2透過ストリップ（1536×1024、セル各768×1024）を使う。人物と車椅子を各セル内に無理なく収め、足・帽子・車輪が切れないこと、中央で人物同士が見た目に接触・連結しないことを確認する。固定ピクセルのガター幅や alpha の微小ノイズだけで不採用にせず、実際のゲーム縮小寸法でコマが分離し、全身とポーズが読めるかを優先する。接触や他セル混入が縮小表示でも見える場合だけ、余白を増やして再生成する。顔とカメラは両コマとも画像左（敵側）を向き、車椅子も画像左向きに固定する。windupでは胴体・肩だけを画面右へひねり、攻撃側の手を肩の高さへ引き、肘を曲げる。followthroughはslash後に攻撃側の腕を画面左下へ伸ばし、反対の腕を腰の画面右側へ引いて、slashと見分けられる胴体の前傾をつける。攻撃側の手はready画像で画面左にある拳とし、両フレームで同じ腕を使う。車椅子は両コマとも座位と車椅子を保つ。画像参照は同一性・キー姿勢の参照に限り、編集元にはしない。合成プレビューでは同名の旧統合絵でなく、存在する場合は `*-character-ready/slash.webp` の人物単体版を優先し、実画像で刀・軌跡が焼き込まれていないことを確認する。刀・軌跡は人物へ描き込まず、フレームごとの武器transformを別に記録する。セル分離が視覚的に確認できたら等分セルで切り出し、足元・車輪の比率を保って保存する。ゲーム内縮小合成で前後のキー姿勢とつながるか確認する。
- 2枚目以降（衣装違い・年齢違い）は、既存のグリッドを **配置の参照** にして「同じ9ポーズを同じコマ・同じ向きで」と指示する。衣装違いなら既存グリッドを編集元にして服だけ差し替える
- 「倒れ」はグリッドだと立ったままになることがある。その1コマだけ単独で生成して差し替える（`key_single.py`）
- 切り出し: `tools/key_grid.py`（振り分けは `keying.split`）。コマの枠では切らず、**濃い部分（alpha>0.5）のかたまりのうち重心のあるコマで最大のものを体とし、残りの見える画素（はみ出した刃・手足・薄い光）は画素ごとに最寄りの体へ付ける**（絵の重心でコマに振り分ける）。かたまり単位だと、透過生成の薄い光で隣のコマの体どうしがつながって失敗する
- **足元より下に丸ごと離れて浮いた小さな塊（光の粒）は捨てる**。付くと切り抜きの下端が足でなくなり、アクスタの台座から浮く。跳んだポーズの足の下を回る大きな光の帯は残す
- 向き: サイドビューで敵が左なので全コマ左向きにそろえる。右向きのコマは番号（0 始まり）を指定して反転する。向きは顔を原寸で確認する。車椅子は、前輪キャスターのx座標が後輪のx座標より小さい場合だけ左向きと判定する。
- ツールを変えたら、採用済みの切り出し結果は出し直さない（元グリッドは保管しない）。次に生成する分から新ツールで切り出し、README の再現手順を正しく保つ

## 7. 歩き（4方向 x 3コマ）

- 4行x3列のグリッドで生成する（上下左右または斜め4方向のいずれか4方向 × 歩き3コマ）。方向名は `down,left,right,up,downleft,downright,upleft,upright`。カメラ角度は採用済み同年齢の正面・横・背面フレームに固定し、一般化した俯角の数値だけで決めない。車椅子はハンドリムをこぐ3コマ。
- **車椅子の歩行周期は各行ごとに3コマ全部を検品する。** 手位置・肘・肩・スポークにコマ間の進行が見えること。3コマ目を一律に「手を離す回復位相」と決めつけない。採用済みの同方向歩行セットがある場合、その3コマの手の接触/離脱・位置を各フレームの正本参照にする。参照と違う動きを新しく足さない。
- 正面・背面はリムが重なって手位置が読みにくい。カメラは既定の俯角（80–85°、標準82°）を保ち、車輪の外側面が見える正面/背面の3/4ビューを指定する。必要なら方向ごとに3コマの横一列で生成し、他の方向との競合を避ける。1方向ストリップは3コマの手・肘・スポーク差を独立検品してから他方向へ展開する。
- 1コマ編集後は、同じalpha閾値（目安 alpha>=8/255）の可視bbox同士で縦横比を比較する。全キャンバスの透明余白や微小なalpha fringeを一方だけに含めない。縦横比が20%以上異なれば構図を再生成し、非等方拡大縮小で車輪・体の比率を変えて合わせない。採用済みセットと同じ共通キャンバスへ等方縮小し、中央・足元そろえで配置する。
- 斜め歩きは位相・ヨー・カメラ・画面内サイズを別々にレビューする。個別編集ではframe1とframe3が同じ接地歩幅へ寄りやすいため、3コマを最終キャンバスで並べ、各コマが参照位相に合い、互いに区別できることを確認する。frame3がframe1を反復した場合は不採用にし、同年齢・同番号の正面/背面を位相正本、既存の斜め候補をヨー・カメラ・サイズ正本、masterを人物正本として脚だけを直す。靴底が見える脚は画面左右ではなく、参照の解剖学的左右と支持脚を指定する。
- 位相はraw画像だけで判定しない。最終共通キャンバスまで縮小すると、後ろ斜めの通過位相で靴の左右間隔が広く見えてストライドへ誤読されることがある。採用可否は白/暗色合成した最終サイズで決める。脚だけの編集でヨーが正面へ戻ったら、その画像は不採用にせず位相土台として使い、採用済み同方向フレームから頭・首・胴体のヨーだけを戻す。カメラ・腕・脚を同じ修正で動かさない。
- 4×3グリッドだけでなく方向別1×3ストリップも、ヨーが正面寄りになったりframe1〜3が同じ歩幅へ潰れることがある。方向か位相が2コマ続けて不合格ならストリップを捨て、同じ方向の採用済みヨー土台・同年齢同番号の単独位相フレーム・年齢masterを使って1候補ずつ生成する。失敗グリッドを採用済み構図の正本にはしない。
- 年齢段階をまとめて揃えるときは、採用済みの前段階12コマを4行×3列の参照シートに合成し、次段階マスターと同時に渡して同じ4行×3列を生成する。参照シートは各コマの比率を保ったまま正方セルへ収め、背景は透明、枠線や文字は加えない。行順・コマ順を固定し、各セルが一対一で対応するよう指定する。隣の行との連結を防ぐため、人物の上下に24px以上（410pxセルの場合）の透明ガターを参照シート内に確保し、生成promptにもセル間の透過を明記する。生成シートを行列で切り出す前に、向き・ポーズ位相・頭身・頭サイズ・車椅子寸法を全セルで確認する。`key_walk.py` が12体を分けられない場合、行境界で強制切断すると帽子や足が欠ける可能性があるため、その候補は失敗とする。透明ガター付きで独立した体を再生成する。対応が潰れる、同一性が崩れる、または寸法差が揃わない場合も失敗として記録し、従来の一コマずつの編集へ戻す。既存採用素材を置き換える場合は新セットの独立レビュー合格後に限る。
- 同時生成＋一括切り出しを第一候補にするが、成功率は方向セットごとに異なる。直交4方向の4行×3列は、採用済み前段階12コマの正確な対応シートと対象年齢マスターを併用した場合に有効だった。一方、斜め4方向のグリッドは行の連結・位相の重複・色縁が繰り返し発生した。斜めグリッドを2回試して位相か分離に失敗したら、再度言い換えて続けず、同方向・同番号の正本1枚と対象年齢マスターだけを使う個別編集に切り替える。
- 頭の大きさ・頭身を揃えるため、同一方向の3コマを1枚の横長1×3ストリップとして同時生成する方法を、斜め歩行の個別生成より先に1方向だけ試す。各コマの位相正本を同じ行に並べた参照シートを使い、3セル間は透明ガターで分ける。採用前に3体が独立して切り出せること、方向・位相・頭身・最終キャンバス寸法が揃うことを確認する。2026-10-24 C001 kindergarten down-right pilot は分離・方向・頭身が揃った一方、frame1/2の手足が似てframe3も接地位相が重なり不採用だった。
- 1×3斜め歩行ストリップが方向・画面内サイズ・頭身を保つ一方でframe1/3の位相を重複させた場合、失敗として記録し、その重複コマを歩行位相の正本にしない。独立レビューで通過位相と確認できた同方向ストリップ中央コマを、カメラ・ヨー・投影・全身の画面内サイズの土台にする。そこから各番号を個別編集し、同年齢・同番号の正面/背面コマは解剖学的な歩行位相だけ、年齢マスターは同一性・年齢・頭身・衣装だけを担わせる。中央コマの通過位相を出力番号に使う場合も正本位相との一致を確認する。編集時は土台の既存ヨーを保ち、「45°回転」を再指示して二重回転させない。
- 土台なしで同年齢の正面/背面歩行コマと年齢マスターだけから斜め方向を個別生成すると、出力が正面寄りになり指定ヨーより浅くなることがある。採用済み同方向の斜め土台がない場合は、方向・目線カメラを確立する試行を先に独立レビューし、そのカメラ/ヨー/全身スケールを歩行位相の正本とは分けて使う。失敗した斜め画像を構図参照に戻さず、別方向の採用セットを安易に代用しない。
- 斜めストリップから切り出したコマを使うとき、WebPの透明プレビューに横帯状のRGBが見えても、それだけで縁汚れと決めない。alphaと白/暗色合成の両方で実画素を確認し、合成後に帯やフリンジが見える候補だけを失敗とする。
- 斜め方向で人物の頭頂・肩・靴の上面が増えて脚が短く見える場合、カメラが俯瞰側へずれている失敗として扱う。ユーザーが目線の高さを指定した場合、カメラを子どもの目線・水平0°・roll 0°・正投影に固定し、人物の向きだけを地面上で変える。各フレームの主参照は同年齢・同番号の採用済み正面または背面（down/up）とし、歩行位相・前後の足位置・最終枠内の身長を参照する。隣接する横向き（left/right）は向きの終点だけを参照させ、歩行位相は主参照から変えない。人物は地面上で垂直軸まわりに45°回転する。「down-left」等をカメラ移動の指示として解釈させない。失敗と判定した既存斜め画像は、ユーザーが修正対象として指示しない限り再生成の構図参照に使わない。
- 斜め歩行の採用済みフレームに俯瞰角や色縁があると判明したら、正本を上書きする前に新候補を独立レビューする。ユーザーが直接透過生成を指定した場合は、最初から透明背景で生成し、`key_single.py ... alpha` で切り出す。緑/マゼンタのクロマキーへ切り替えない。
- 成長段階の頭身・頭サイズを揃えるには、次段階マスターと前段階の採用済み12コマを同時に使い、行列とコマ対応を固定する。前段階シートは配置・歩行位相・人物/車椅子の相対寸法の正本、対象段階マスターは顔・年齢・衣装の正本として明確に役割を分ける。全セルを並べ、頭身・頭サイズ・車輪寸法・足元位置を世代間で比較してから切り出す。
- 個別編集でも手の移動が出力で縮む場合、フレーム2/3の正本をそれぞれ直接参照し、手位置の差を最終共通キャンバス上のピクセルで測る。出力の見た目だけでなく、正本と同じ接触/離脱状態かを独立レビューで照合する。壮年right-downの調整では307×388出力上で約18px左・16px下の手位置差が有効だったが、数値を他方向へそのまま流用せず、方向別の正本位相に合わせる。3コマ目を全方向共通の「離す」位相にしない。
- 斜め上などの全身が大きく見える視点では、帽子・靴・キャスターが出力端に触れる候補がある。共通キャンバスへ納める際は縦横比を変えずに等方縮小し、必要な候補は左右に各4%以上・上下に6%以上の透明余白を確保して中央・足元を整える。これは端接触がある候補への均一なフィットであり、すべてのフレームを一律に小さくする指定ではない。余白追加後も原寸で欠け・位置ずれを確認する。
- 位置指定は視点ごとに曖昧な「rearward/frontward」だけに頼らない。正面/背面ではセル内の画面座標や車輪リムの上下象限を使い、1→2の手位置差（例: セル高の20%以上）と肘の屈伸を併記する。左右の手は「画面左側/右側の車輪」と指定する。側面は車輪の前後/上下象限を明示する。
- 同じ向きでコマ間の姿勢差が2候補続けて崩れたら、言い換えだけで生成を続けない。まず採用済みの同方向・同コマ番号を正本参照にする。1枚のstripへ複数参照をまとめても同じポーズへ潰れる場合、コマごとに独立して編集し、各出力に対応する正本フレーム1枚と対象年齢マスターだけを渡す。「姿勢・手位置・車椅子・カメラは保持し、対象マスターに合わせて人物の年齢と衣装だけ変更」と指定する。1/2/3の出力を並べ、参照との対応を検品してから保存する。採用済み参照がない場合は別方向の採用セットから代用せず、独立した1方向生成として再設計する。
- 生成後、見た目を実際に確認してから `key_walk.py` の方向名を割り当てる。2・3行目は指示と逆になることがあるため、プロンプト上の行名やコマンドの想定だけで方向を確定しない。検品で左右ファイル名が逆なら、切り出し引数を直してから保存する。
- **2行目と3行目の向きが入れ替わって出ることが多い。同じ向きに2行出ることもある**。顔を見て行ごとの向きを決め、切り出しの引数で指定する。同じ向きなら片方の行を反転する（`key_walk.py ... flip_rows`）
- 切り出し: `tools/key_walk.py`。key_grid と同じ重心方式で振り分け、**全コマを共通の枠に入れ、足元（下端）をそろえる**（コマごとにタイトに切ると歩きが揺れる）
- コマ数・枠はエンジンのフィールド仕様が決まったら合わせる（今は仮）

## 8. 透過

- **既定は「透過のまま生成」**（2026-10-14 に統一）。プロンプトに transparent-output request と「Do NOT key out or post-process」を書き、`file` で `RGBA` を確かめる。切り出しツールには `alpha` を渡す
- 理由: 同じグリッドで比べた結果、クロマキーは刃・リボンの青い光に緑が混ざって濁った。透過の直接生成は光が自分の色のまま半透明で残り、写真背景になじむ。体の縁はどちらもきれい
- 生成を安定させたいときは、クロマキー背景でポーズ・構図を決めてから、その画像を編集元に「Change ONLY the background: make it fully TRANSPARENT」で透過にしてよい（小学生のセットはこの2段で作った）
- **クロマキーは代替**（RGBA で返らないとき）。緑 `#00ff00`、緑の服や帽子のキャラ（シャー）はマゼンタ `#ff00ff`。「perfectly flat and uniform, no shadows, no floor」と書き、ツールに `green` / `magenta` を渡す
- 抜き方の処理は `tools/keying.py` に1つだけ置き、key_grid / key_walk / key_single はそれを使う
- 幼稚園期の既存素材（2026-10-14 以前）はクロマキーで作った。作り直すかは kako-jun が決める
- 透過後は暗い背景と台帳で実在を確認した背景（`assets/images/fields/`）の両方に重ねて、縁のにじみ・欠け・光の色・他のコマからの混入を確認する。アクスタの枠・台座・影は描画側が後がけするので、素材に含めない
- 画像ビューアがalpha=0画素のRGB値を黒や色帯として表示することがある。表示だけで背景残りと判定せず、RGBA alpha extremaとalpha>5のbboxを測り、白・暗色合成で見える背景、glow、輪郭を確認する。alpha=0画素内だけの色は採否に使わない。
