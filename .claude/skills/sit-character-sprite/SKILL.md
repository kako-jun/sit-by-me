**画像の保存形式（#68決定、2026-10-19）**: imagegenの出力（PNG）→切り出し→**WebP（非可逆・品質85・アルファ保持）**にして正本パスへ保存する（`magick in.png -quality 85 out.webp`、または `verification/characters/tools/key_*.py` が直接WebPで出す）。PNGは残さない（name-name のTUIは WebP のみデコードできる）。実寸（不変）・アルファ（`magick in.png -alpha extract` と変換後WebPの同コマンドを `compare -metric AE` で比べAE=0）の検査はWebPで行う。寸法ゲートの基準（1920×1080等）は変えない。

Sit by Me の4人（と子供3人、不良など人物）の絵を、生成 → 確認 → 透過・切り出し → 保存 → 記録の順で作る。敵は `sit-enemy-sprite`、召喚獣は `sit-summon-sprite`、フィールド背景は `sit-field-background`、戦闘背景は `sit-battle-background`。ここは人物スプライトだけ。

## 一意解釈ゲート（このスキルの全行より優先）

人物生成の条件には、参照画像パス、人物ID、年齢段階、衣装名、向き、ポーズ名、コマ数、画像寸法、色名、または原文にある固有名だけを使う。`少し`、`やや`、`自然`、`十分`、`明瞭`、`目立つ`、`適切`、`雰囲気`、`おおよそ`、`〜風`は生成条件として禁止する。これらの語を眉・目・口・手・足・衣装・向き・座標・色へ変換できなければ生成しない。

## 曖昧なミニチュア指定の禁止

人物素材はミニチュア背景ではない。人物に「模型風」「手作り風」を追加してはならない。人物を背景へ合成する依頼でミニチュア材料の指定が必要な場合は、このスキルで補完せず、背景側の `sit-field-background` または `sit-battle-background` の材料・道具宣言を正本にする。

先に `uv run python3 scripts/content_ledger.py query character Cxxx --form FORM-xxx --gate` を実行し、その出力全体（人物の特徴、形態、素材の採否、適用する決定、未解決ゲート）を生成入力とレビューへ渡す。`Cxxx` と `FORM-xxx` は対象ID・形態IDで置換する。ゲート失敗なら生成を止め、台帳の未決を確認する。正本は `docs/ledger/人物.yaml`・`人物形態.yaml`・`素材.yaml`・`決定.yaml`。経緯は各行の出典、技術運用は `docs/assets-policy.md` を読む。C IDがない子供・不良などはIDを推測せず、人物表に追加する決定を待つ。

別のゲームのスプライトを作るときは、このスキルをそのまま使わない。ツール（`verification/characters/tools/`）と手順の考え方を流用し、そのゲームの設定を正本にする。

## 0. 原則

失敗の来歴（完全prompt・参照・実寸/検査結果・判定理由）はIssueまたはレビュー文書に記録し、失敗画像はリバート／削除する（バイナリを別置き場に保存しない）。

- **生成ごとに会話へ貼る**（SendUserFile。URL だけ・まとめ見せ・選別は不可）。縮小した一覧で確認してよいのは自分の検品用だけで、kako-jun には元画像を送る
- **やることは生成前に Issue に書く**。決定（kako-jun の指示）は docs と Issue に即記録する
- **作業用の画像はスクラッチに置き、採用したらすぐリポへコミットする**。スクラッチはセッション再開で消える（2026-10-14 実害）。消えたら `~/.codex/generated_images/` から時刻と寸法で回収できる
- 生成はまず対象1件ずつ検査する。複数案や並列生成は依頼された範囲に限定する。
- 創造的な選択（案 a/b、色、意匠）は kako-jun が決める。任されたら推しを理由つきで出して進める
- 複数案が依頼された場合だけ案を並べる。採用済みの絵は指摘点だけを直す。
- **年齢・制服・地域・設定の社会的な決まりは推測で決めない**。決定は docs/decisions.md にある。ない点は聞く（2026-10-14: 小学校にセーラー服はない、北陸は小学生も制服、など推測の誤りが出た）

## 1. 生成の呼び出し

利用可能な `imagegen` スキルを読み、組み込み `image_gen` で生成・編集する。参照は実画像で渡し、identity／layout／edit target の用途を明示する。ツールに無いモデル・quality・size引数や古い `codex exec` 呼出しを必須にしない。利用不能ならコードで代作せず原因を記録する。

生成前に完全prompt・設定原文・参照一覧を独立promptレビューへ渡す。まず1候補を生成し、原本・完全prompt・参照・寸法・結果を記録する。`file` 等で実寸を測り、透過素材はalpha=0画素の存在も検査する。RGBA形式名だけで透過と判定しない。原寸で顔・衣装・向き・全コマ・縁を目視し、切り出し後も独立画像レビューを通す。失敗は判定・prompt・測定値をIssueまたはレビュー文書に `failed` と記録して画像はリバートし、自動再生成しない。保存は正本パスへの直接上書きで、合格ならコミット、不合格は git でリバートする。**使う可能性のあるテイクは次を生成する前にコミットする**（未コミットの新規ファイルは上書きで消える）。採用状態は置き場でなく台帳・Issueのstatusで管理する。

## 2. マスター三面図（同一性の基準）

- 1枚に **正面・横・背面の全身**、暗いグレーの無地背景、1536x1024
- 以後の生成はすべてこのマスターを参照する。マスターが決まるまでポーズを量産しない
- 顔立ちは人種・年齢を明記する（日本人の顔立ち、一重、垂れ目など。4人の特徴は art-direction）。金髪の全面指定は白人顔に寄るので、メッシュなど部分で入れる
- AI の定番顔・テンプレ服にしない。キャラごとの特徴（髪の一部の色、眼鏡、マフラー、大きな帽子など）を入れる

## 3. 服だけ・部分だけ変える（編集）

- 既存のマスターを **編集元** にし、「Change ONLY …／Keep EVERYTHING ELSE identical」で変える部分を1点に絞る（服を園服に、鞄を外す、靴を上履きに、スパッツを外す、帽子を大きく、マフラーを足す）
- 顔・髪・帽子・構図を保ったまま衣装差分が作れる。新規生成より同一性が高い
- 1回の編集で変えるのは1〜2点まで

## 4. 年齢段階

- 前の段階の採用画像を参照して、**1段ずつ** 歳をとらせる（幼稚園 → 小学生 → 中高生 → 青年 → 壮年）。幼稚園から大人へ一気に飛ばすと顔が子供のまま残る
- 「顔と体がその年齢に明確に見えること（大人の骨格、子供の丸みなし）」を書く。若く出たら顔だけ編集で直す
- 年齢ごとに服と帽子のデザインを変える。髪の色・特徴は引き継ぐ。服の色は大人ほど落ち着かせ、髪は派手なまま（decisions）
- 壮年編に出るのは主人公・配偶者・子供3人。友達2人は離脱するので壮年版は要らない

## 5. 車椅子版

- 立ち姿のマスターを編集元にし、同じ三面で車椅子に座らせる
- **切断面は描かない**。膝掛け・コートで太ももから膝を覆い、片足だけ出す。素の切断描写は出力モデレーションで約半数が拒否される
- 「fully clothed」「wheelchair user」「dignified everyday look」と書く
- 戦闘もフィールドも車椅子のまま（立たせない）。戦闘ポーズは立ちのグリッドを配置の参照にして「seated in the wheelchair in every cell」と書き、9 ポーズを読み替える（突進=ハンドリムを強くこぐ、必殺技=前輪を上げた突進、など）

## 6. 戦闘ポーズ（3x3 グリッド）

- 9 ポーズを **1枚の 3x3 グリッド** で生成する（同時に作ると同一性が保てる）。並び: 待機 / 構え / 踏み込み / 斬る / 被ダメージ / 倒れ / 詠唱 / 必殺技 / 勝利（決めポーズ。年齢をまたいで同じ）
- 2枚目以降（衣装違い・年齢違い）は、既存のグリッドを **配置の参照** にして「同じ9ポーズを同じコマ・同じ向きで」と指示する。衣装違いなら既存グリッドを編集元にして服だけ差し替える
- 「倒れ」はグリッドだと立ったままになることがある。その1コマだけ単独で生成して差し替える（`key_single.py`）
- 切り出し: `tools/key_grid.py`（振り分けは `keying.split`）。コマの枠では切らず、**濃い部分（alpha>0.5）のかたまりのうち重心のあるコマで最大のものを体とし、残りの見える画素（はみ出した刃・手足・薄い光）は画素ごとに最寄りの体へ付ける**（絵の重心でコマに振り分ける）。かたまり単位だと、透過生成の薄い光で隣のコマの体どうしがつながって失敗する
- **足元より下に丸ごと離れて浮いた小さな塊（光の粒）は捨てる**。付くと切り抜きの下端が足でなくなり、アクスタの台座から浮く。跳んだポーズの足の下を回る大きな光の帯は残す
- 向き: サイドビューで敵が左なので全コマ左向きにそろえる。右向きのコマは番号（0 始まり）を指定して反転する。向きは顔を原寸で確認する。車椅子は、前輪キャスターのx座標が後輪のx座標より小さい場合だけ左向きと判定する。
- ツールを変えたら、採用済みの切り出し結果は出し直さない（元グリッドは保管しない）。次に生成する分から新ツールで切り出し、README の再現手順を正しく保つ

## 7. 歩き（4方向 x 3コマ）

- 4行x3列のグリッドで生成する（下・左・右・上 × 歩き3コマ）。カメラの鉛直下向き角は80°以上85°以下とする。車椅子はハンドリムをこぐ3コマ。
- **2行目と3行目の向きが入れ替わって出ることが多い。同じ向きに2行出ることもある**。顔を見て行ごとの向きを決め、切り出しの引数で指定する。同じ向きなら片方の行を反転する（`key_walk.py ... flip_rows`）
- 切り出し: `tools/key_walk.py`。key_grid と同じ重心方式で振り分け、**全コマを共通の枠に入れ、足元（下端）をそろえる**（コマごとにタイトに切ると歩きが揺れる）
- コマ数・枠はエンジンのフィールド仕様が決まったら合わせる（今は仮）

## 8. 透過

- **既定は「透過のまま生成」**（2026-10-14 に統一）。プロンプトに transparent-output request と「Do NOT key out or post-process」を書き、`file` で `RGBA` を確かめる。切り出しツールには `alpha` を渡す
- 理由: 同じグリッドで比べた結果、クロマキーは刃・リボンの青い光に緑が混ざって濁った。透過の直接生成は光が自分の色のまま半透明で残り、写真背景になじむ。体の縁はどちらもきれい
- 生成を安定させたいときは、クロマキー背景でポーズ・構図を決めてから、その画像を編集元に「Change ONLY the background: make it fully TRANSPARENT」で透過にしてよい（小学生のセットはこの2段で作った）
- **クロマキーは代替**（RGBA で返らないとき）。緑 `#00ff00`、緑の服や帽子のキャラ（シャー）はマゼンタ `#ff00ff`。「perfectly flat and uniform, no shadows, no floor」と書き、ツールに `green` / `magenta` を渡す
- 抜き方の処理は `tools/keying.py` に1つだけ置き、key_grid / key_walk / key_single はそれを使う
- 幼稚園期の既存素材（2026-10-14 以前）はクロマキーで作った。作り直すかは kako-jun が決める
- 透過後は暗い背景と台帳で実在を確認した背景（`assets/images/fields/`）の両方に重ねて、縁のにじみ・欠け・光の色・他のコマからの混入を確認する。アクスタの枠・台座・影は描画側が後がけするので、素材に含めない

## 9. 保存と命名

- 人物IDは C001=オトン（旧otton）、C002=ナム（旧nam）、C003=シャー（旧shah）、C004=ペー子（旧peiko）。保存先は `assets/images/characters/Cxxx/`。旧名前接頭辞を同じ人物IDへ置換し、年齢・衣装・車椅子差分は保持する。マスターは `Cxxx/masters/Cxxx-{age}[-uniform|-wheelchair].webp`。
- 戦闘ポーズは `Cxxx/poses/Cxxx-{variant}-{pose}.webp`。既存suffixの年齢・衣装・ポーズを落とさない。
- 歩きは `Cxxx/walk/Cxxx-{variant}-walk-{dir}-{1,2,3}.webp`。既存suffixの方向・コマ番号を保持する。
- 元のグリッド（切り出し前の原本）は保管しない（#68決定、2026-10-19。過去分は git 履歴 `1bb09d0` から復元）。切り出し結果の `poses/`・`walk/`・`masters/` は正本パスへ直接上書きし、`git add` は名指し
- 手順や引数を変えたら `verification/characters/tools/README.md` と `docs/assets-policy.md` を同じコミットで直す
- 採用・決定は Issue #3（人物）・#5（ポーズ）に記録する

## 10. 完了報告

生成したもの・採用したもの・コミット（ハッシュ）・記録した Issue・未決事項（kako-jun に決めてほしいこと）を報告する。

## 禁止事項

- Co-Authored-By をコミットメッセージに付けない
- --no-verify を使わない
- .env やクレデンシャルをコミットしない
- 指示されていない「改善」をしない
- 画像を ImageMagick や PIL で描いて生成物の代わりにしない
- 生成物に独自の性的・不適切判定をして削除・停止しない

共通（#68運用）: 合格済みの正本を上書きする前に、現行がコミット済みか確認する。不合格テイクをコミット済みにしてしまった場合は `git revert <commit>`、または `git checkout <旧commit> -- <path>` で戻す。
