# Sit by Me 敵スプライト

**画像の保存形式（#68決定、2026-10-19）**: imagegenの出力（PNG）→切り出し→**WebP（非可逆・品質85・アルファ保持）**にして正本パスへ保存する（`magick in.png -quality 85 out.webp`、または `verification/characters/tools/key_*.py` が直接WebPで出す）。PNGは残さない（name-name のTUIは WebP のみデコードできる）。実寸（不変）・アルファ（`magick in.png -alpha extract` と変換後WebPの同コマンドを `compare -metric AE` で比べAE=0）の検査はWebPで行う。寸法ゲートの基準（1920×1080等）は変えない。

候補の来歴（完全prompt・参照・実寸/検査結果・判定理由）はIssueまたはレビュー文書に記録する。候補の削除・移動・リバートは、人間が不採用を明示してから行う。採否待ちの候補を勝手に削除しない。

敵 `M` の戦闘用マスター画像だけを扱う。生成前に `docs/content-registry.md`、`docs/monsters.md` の対象行、必要なら `docs/dungeon-enemies.md`、`docs/art-direction.md`、`docs/assets-policy.md` を原文のまま読む。`ready` は最終採用済みの状態であり、生成の前提条件ではない。対象画像そのものに未解決のTBDがある、またはサイズ種別が矛盾する場合だけ生成しない。

## 一意解釈ゲート（このスキルの全行より優先）

生成入力・検査には、敵ID、敵台帳の原文、参照画像パス、キャンバスのpx寸法、グリッド種別、画面座標、色コード、個数、材料名、またはこの文書が定義する角度だけを使う。`少し`、`やや`、`大きい`、`小さい`、`自然`、`十分`、`雰囲気`、`おおよそ`、`〜風`、`右向き`だけを実行語として使わない。数値または原文へ変換できない条件が残る場合は生成しない。

## 向き: 真右の横顔を禁止する

キャンバス座標は右を `+x`、下を `+y` とする。敵の頭部と胴体のヨー角は、カメラ正面を `0°`、真右の横顔を `90°` としたとき、**`45°`** にする。顔の正面面と右側面の両方を画像内に出す。頭部または胴体が `90°` の真右横顔だけになる出力は失格とする。

瞳の視線ベクトルだけは `+x`（真右）でよい。瞳が `+x` を向いていても、頭部・胴体のヨー角は `45°` のままにする。敵マスターは戦闘画面の左側に置かれ、`+x` 側の味方へ向く。レンダラーが反転して使うため、左右で意味が変わる文字、ロゴ、片側だけの記号を画像に入れない。例外として **M031 カッペボーイ**の段ボール仮面には、敵台帳が指定する「へのへのもへ」だけを描いてよい。「じ」や他の文字・ロゴは禁止。M031の独自紫タコのマークも許可する。アクリル台座、輪郭線、接地影は描かない。台帳に頭部・胴体・瞳のいずれも無い現象・無生物には、その不存在を補って描かず、当該確認項目をN/Aとする。

## グリッド種別と出力枠

通常敵・中ボスは次の4種だけを使う。ラスボスはこの4種に制限せず、台帳で先に明記した大型枠（例: `2x6`）を使える。生成前に対象行から `gridClass` を一つ確定し、プロンプト・ファイル記録・レビューに同じ値を記す。

| `gridClass` | 戦闘グリッドの占有セル |
| --- | --- |
| `1x1` | 横1 × 縦1 |
| `2x1` | 横2 × 縦1 |
| `1x2` | 横1 × 縦2 |
| `2x2` | 横2 × 縦2 |
| `2x6`（ラスボスのみ） | 横2 × 縦6 |
| `3x2`（M013 ツインブタニアのみ） | 横3 × 縦2（kako-jun 個別指定 2026-10-22。通常の中ボス枠の例外） |

`gridClass` は論理的な占有セルであり、生成画像のpx寸法・縦横比・外接矩形の大きさを指定しない。`3x2` は M013 専用で、他の敵には使わない。M013 の横長構図は対象行またはpromptで別途数値指定する。px寸法とalpha外接矩形は技術情報として記録する。端の画素接触は自動不採用の条件にせず、切れて見えるかを人間が目視で判断する。

台帳行にサイズ種別がある場合はその値を使う。台帳行に無い通常敵だけは、生成前の敵設計の幅÷高さが `1.80以上` なら `2x1`、`0.55以下` なら `1x2`、その間なら `1x1` とする。中ボスは `2x1`、`1x2`、`2x2` のいずれかを、ラスボスはその3種または `2x6` を台帳行に明記してから生成する。例外は表に名指しされた M013 の `3x2` だけ。ボスの種別を比率から推測してはならない。

## 生成・保存・検査

生成前に完全prompt・台帳原文・参照画像と各用途を `sit-artifact-redteam` のpromptレビューへ渡す。生成は利用可能な `imagegen` スキルと組み込み `image_gen` を使い、呼び出しに `transparent_background: true` を明示する。返却寸法・alphaは保証されない。`file` 等の実寸と、alpha=0の画素が存在すること、alpha>0の最小外接矩形の `(x,y,width,height)` と幅/高さ比率を測定・記録する。RGBAという形式名だけで透過を認定しない。表示UIの白・黒・市松は透過失敗の根拠にせず、実ファイルの四隅alphaとalpha最小値を測る。RGBに市松が焼き込まれた場合は不合格。背景だけの再編集にもalphaが無い場合は、画像の色に存在しない一様な緑またはマゼンタの背景へ切り替え、`verification/characters/tools/key_single.py` のクロマキー処理を使う。キー色の本体混入、背景むら、縁の残色があれば不合格とし、採用候補を加工で通過させない。頭部と胴体の正面面・右側面は該当する対象のみ原寸で個別に確認する。人間の採否決定前に候補をリバート・削除・移動しない。勝手な再生成・引伸ばしで通過させない。

1. 原文台帳の敵ID、家族、出現場所、魔法、禁止事項を削除・要約・補完せずに生成入力へ入れる。
2. 透過背景で1候補だけ生成し、生成元の候補ファイルは採否まで保持する。人間に候補を見せ、採用を明示された後だけ、WebP（品質85・アルファ保持）へ変換して正本 `assets/images/enemies/Mxxx.webp` に保存する。M番号は敵台帳を正本にする。人間が不採用を明示した後だけ、候補を削除・移動・リバートしてよい。正本へ保存後は名指しでコミットする。採用状態は置き場でなく台帳のstatusで管理する。加工前の原本（`raw/`）は保管しない（#68決定、2026-10-19）。
3. 原寸で、`45°` の頭部・胴体、瞳だけの `+x` 視線、`gridClass`、透明背景、文字・ロゴ・台座・接地影なしを確認する（M031は仮面の「へのへのもへ」と紫タコのみ例外）。px寸法とalpha外接矩形は記録し、端の接触は人間の目視確認へ回す。
4. 採用候補は `sit-artifact-redteam` の独立画像レビューへ渡す。生成前計画と生成後の来歴・失敗は Issue #17 または対象Issueへ記録するが、採用決定前に採用済み/`ready`へ変更しない。

共通（#68運用）: 合格済みの正本を上書きする前に、現行がコミット済みか確認する。不合格テイクをコミット済みにしてしまった場合は `git revert <commit>`、または `git checkout <旧commit> -- <path>` で戻す。
