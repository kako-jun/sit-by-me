## 1. 正本と出力

- 会話や演出を含むイベントの正本は台帳。`script.md`、`events/E001.md` 等は台帳から生成するスナップショット（#250）。出力先と ID の対応は同 Issue の方針で、本番生成器や詳細の設計は未着手。
- 現在の `docs/scenario-registry.md` は E001〜E029 の初期目次。TBD があれば blocked。`NPC配置.yaml` と `NPCセリフ.yaml` の N-* は探索時の参照点であり、イベント一覧の代わりではない。
- YAML は既存表と同じフラットな行、すべて引用文字列、空欄は `""`、複数行は `|-` を使う。以下の表名・列・試作 ID は**設計案**で、現行の台帳ビルドには登録していない。
- 既存 E は用途と粒度が混在する。E を既存のまとまりとして維持し、その中の順序付き項目を持つ案を下に試す。実行時のシーン ID を E と同一にする方針と、戦闘中の複数条件をどう結ぶかは #250 と照合して決める。

## 4. 初期の雛形案（現行の構成ではない）

当初は2表に分ける案だった。現行の試作はイベントごとに1ファイルとし、以下は検討の履歴として残す。

場面と順序項目を分ける。1行1項目とし、同じ戦闘の途中条件を複数表現できるようにする。表の境界、採用する列、ID の採番は未決。ファイル名は他表にならった案。

### `イベント.yaml` の案 — 物語上のまとまり

| 列 | 意味 |
|---|---|
| イベントID・ERA | 既存 E ID・時代 |
| 名称・目的 | 対象と、その場面でプレイヤーに伝えたいこと |
| 開始条件・終了条件・前後 | 発火、終端、前後のイベントや結果別の遷移 |
| MAP_ID・参加者・対象 | 場所、人物、敵などの既存 ID |
| 会話量の目標・上限・往復 | 目標値と定義。未決は空欄で、単位を併記 |
| 出典・状態・未決・備考 | 決定の根拠、執筆の段階と実行可否を分けて記す |

### `イベント進行.yaml` の案 — 場面内の順序と条件

| 列 | 意味 |
|---|---|
| 進行ID・イベントID・順序 | 安定した識別子、所属、表示・評価順 |
| 場面 | フィールド／戦闘開始／戦闘中／戦闘終了後など |
| 条件・繰り返し | 入場・行動・HP・ターン等、成立する条件と回数 |
| 種別・対象 | 会話、演出、戦闘開始、参戦、復活、強制、逃走、終了、遷移など |
| 話者・本文・演出 | 既存人物 ID、文章、音や動き。内容未決なら空欄 |
| 結果・次イベントID | 勝利・敗北・中断・逃走を区別して移行先を記録 |
| 出典・状態・未決・備考 | 根拠・仮稿か決定か・未確定項目 |

**要設計:** 順序だけでなく、戦闘中は条件が同時に成立した時の評価順・1回限りか・分岐後に残りを実行するかを表せること。会話本文を別表へ分けるか、同じ項目の繰り返しや複数話者をどう表すかは、E001 の試作をレビューして決める。name-name の脚本制御戦闘は行動の境目で条件を評価し、台詞・参戦・終了等は各ルール1回。中断時は勝敗も報酬もない（name-name `docs/spec/markdown-v0.1.md` の脚本制御戦闘）。一枚絵フィールドの NPC 脚本内の `[戦闘:]` は未対応と同仕様に記述されているため、台帳の表現と実行可能性は分けて扱う。
