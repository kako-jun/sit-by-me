# 体内MAPのモック保存設計と位置合わせツール（試作・2026-10-22）

#142 の kako-jun 指示（「もとにしたモックも残せばいいのでは」）への設計提案と試作の検証記録。2026-10-22 続報: 17枚へ適用し、2値マスク・出口候補・モック保存まで出した（§4〜§8）。red-team（2回）済み・kako-jun の2点の承認（2026-10-23）済みだが、遷移の範囲値とランタイム扱いが TBD のため **ready ではない**。

## 1. モックの保存方針（提案）

- **置き場**: `docs/production/body-mocks/`（設計資料。runtime 資産ではない）。理由: `assets/` は runtime 正本（assets-policy・asset-layout.md）で、モックは配信しない。`verification/` は「検証画像置き場を作らない」運用（asset-layout.md 保存運用）と衝突し、台帳外の置き場が増える。モックは**ゲームの設計正本の一部**（床の形・出口の辺と範囲・迷路の格子）なので docs に置く。
- **形式**: `BDY-xx-clean.webp`（清書図 1920x1080、**可逆WebP**。床・地形・壁の単色の正確な画素が要る）、`BDY-xx-mock.webp`（通常版・注記付き。目視資料なので非可逆WebP品質85でよい）、`BDY-xx.json`（幾何、下記）。17枚+BDY-17-B。PNG は残さない。
- **再生成可能性**: 画像・JSON とも `body_layout.py` と `body_geometry_json.py` から再生成できる。docs へ置くのは「採用時点の版」の凍結（SPECS が将来変わっても採用画像との対応が残る）。JSON に `schema` を持たせ、採用画像の sha256 との対応は台帳（map-asset-registry）側に書く。
- 試作の JSON は `verification/body-layout/geometry/BDY-xx.json`（17枚+index.json、新規・未コミット）。移動時は `docs/production/body-mocks/` へ。

## 2. 座標系

基準は「模型の天面の矩形に対する比 (u,v)」。NPC・イベント位置はこれで書く（モックの形状に追従して画像へ写るため）。画像座標への写像は `body_register.py` が出す 2x3 行列（モック px → 画像 px）。単純に 1672/1920 倍ではない（採用画像の天面は 1,410〜1,430px 幅で、縮尺・位置が画像ごとに違う）。

## 3. 位置合わせの方式と限界（`.claude/skills/sit-field-background/tools/body_register.py`）

```
uv run --with pillow --with numpy --with scipy --with opencv-python-headless python3 -I \
  .claude/skills/sit-field-background/tools/body_register.py BDY-04 \
  assets/images/fields/reference/body-brain-maze-bdy04-adopted.webp --out OUTDIR \
  [--npc "名前:u,v;名前:u,v"] [--clearance 12] [--allow-rotation] [--clean PATH] [--geometry PATH]
```
出力（OUTDIR）: `-register.json`（変換・残差・信頼度・床の差・位相・NPC）、`-overlay.png`（モック床=青＋輪郭=黄＋天面=紫の枠）、`-floor-cut.png`（床の二値、画像と同寸）、`-diff.png`（緑=両方・赤=モックのみ・青=画像のみ）、`-topology.png`（出口の枠・中心線・迷路格子・NPC）。

1. **天面 rect**: `check_body_image.measure_layers`（机→縁取り→波形→天面）を再利用。期待から60px超ずれる／層が読めない時だけ期待の rect。
2. **床色モデル**: チェッカーの床色推定と、モック床の芯（初期変換で写して内側）の中央値を比較し、食い違えば芯の色を採る（BDY-07 は推定がテラコッタ地形色 203,151,115 に誤り、芯から 233,205,171 に是正）。分布は共分散（マハラノビス）。
3. **精密化**: 初期変換は rect 合わせ（拡大＋平行移動）。モック床境界点 →画像床境界（色だけで抽出）の距離変換 chamfer（上位70%平均）＋「縁に届く床区間の両端」の位置ずれ項（斜めの帯が帯の向きに滑る開口問題の対策）。2パス（芯の色を作り直す）。自由度 T / S(±2%) / SR(回転±2.5°) / A(縦横比)を全部試し、**既定は T か S の最小**（真上撮りで回転は物理的に無く、斜めの帯1本の MAP では回転が傾きの描き分けを吸収して誤一致するため。SR/A は診断値として表に出し `--allow-rotation` で採用）。
4. **信頼度**: inlier（12px×倍率以内のモック境界点の割合）と平均で HIGH(>=0.8 かつ平均<=4px)/MID(>=0.5)/LOW。
5. **床の切り出し**: 位置合わせ後のモックを種に **GrabCut**（確実な床=モック床を18px侵食、確実な地形=天面の外のみ、他は「らしい」。モック地形を確実にしないのは画像の方が床が広い構造差を拾うため）。後処理: モック床の芯と連結しない成分を捨てる（飾りのボタン・毛糸）、モック床境界沿いの幅<約14pxの「画像のみ床」を壁の帯（面取り・段ボール帯）として blocked 側へ戻す。
6. **NPC**: `(u,v)` → モック px → 変換 → 画像 px → 床の縁から clearance 以上の最寄り点へ寄せる。戻り値は寄せ距離 px・元が床上か・寄せ後の (u,v)。

**限界（実測で確認）**
- モックと画像の**形が違う**とき（BDY-07 の通路幅・傾き、BDY-09 の通路幅）は位置合わせでなく「差」として出る。これは仕様どおり（差分を報告するツール）だが、単一の斜め帯 MAP は inlier が低く出る。
- 面取り・影の帯（約10〜25px）で床の境界が曖昧。BDY-04 は S 側の暗い帯、BDY-09 は上辺の明るい斜面（約25px）。GrabCut は明るい斜面を床に含める（BDY-09 の「画像のみ床」19%の大半）。**壁の足元をどこと見なすか**は人の判断（未決事項）。
- 道が1本の帯（BDY-07/09/13）は帯の向きの並進が弱拘束。縁の出口位置項で抑えているが、出口の位置ずれ（最大 43px）は残る。
- 折れ点検出（スケルトン）は ±約17° の雑音（BDY-07 のモックでも直線に16.9°の偽折れ点）。端は道幅1倍ぶん除外。
- GrabCut は画素色のみ。色が床と同じ飾り（毛糸・ボタン）が床に接するとき、細い付着は開閉で落ちるが太い付着は残りうる（今回の5枚では発生せず）。

## 4. 2値マスクと壁の足元の定義（kako-jun 決定、#142 最新コメント）

体内のマスクは **white（通れる）／black（通れない）の2値だけ**。assist（#FF9D00）は使わない。standing = wheelchair = 同一の mask。

- **壁の足元の定義**: 床（クリーム）の領域だけが white。壁の帯（段ボール＋毛糸）・面取りの斜面・影・地形・土台縁・机は black。
- **マスクの真実は採用画像の床の見え**。位置合わせの信頼度が LOW（BDY-07・15・16）でも画像の床を正とし、モックは更新しない（差分として register.json の `adoption.note` に記録）。
- **床色基準の切り出し**（`strict_floor_by_color`）: GrabCut は種の補助に留め、最終の床は「GrabCut の床の芯（縁から22px以上内側）の色（中央値＋共分散）からのマハラノビス距離 < 5」の画素だけ。median(5)→opening→芯と連結する成分だけ→小さな穴（床の汚れ）だけ埋め→壁側へ1px侵食→1500px²未満の切れ端を捨てる。閾値3だと床の壁際の明るさの勾配まで削る（BDY-04 で縁から約10px）ので5。BDY-09 の壁外の明るい面取り斜面は床色から外れて black に戻り、画像のみ床は19%→構造差0（細い境界差3%）。BDY-04 の南辺の影の帯も black。
- **床色の連続に限る出口の延長（2026-10-23 修正）**: 出口の喉の延長（`extend_exit_throats`）は、影で暗い床（md<10）を縁の内側・出口の区間の幅の中だけに許す（縁の外・区間の外へは延ばさない）。仕上げ（`finalize_cut`）で、①床の芯の色（延長前の white の芯。md2）が閾値12を超える white 画素（帯・壁の色。BDY-09 W の RGB(167,123,81) 前後など）を除く、②縁（rect）の外の white は md<5 の床色だけ残す（BDY-07 E のテープの縁の色など）、③出口の縁ぎわ（縁から内外12px）の幅5px未満の突起を開閉で落とす、④white に囲まれた小さな穴（<=100px²）は穴の全画素が床色のときだけ埋める（BDY-10 N の上縁の穴4個=30px）。足すのは④だけ。
- 出口の検出は縁から30px以内（段ボール帯の下の影で床が縁から約10〜15px離れる画像がある。BDY-07 N は14px、BDY-10 N は15px）。出口ごとの `floor_gap_to_edge_px` を links に記録（床と縁の間の black の帯。ゲームの遷移トリガーが辺上の範囲で判定するなら通れるが、床と縁の間の隙間の扱いは範囲値とあわせて TBD）。
