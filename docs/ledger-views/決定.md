### TRM.ledger-master（2026-10-23・有効）

台帳（docs/）が情報の唯一のマスター。決定は先に決定ブロックへ書き、Issue は決定IDを参照するだけ。plan・装飾プール・接続JSON・prompt は台帳から導出または参照し、決定文を複写しない（座標・寸法・個数などの構造データだけJSONに持つ）。

> 「Issueにだけかくなんてだめだ。台帳がマスターだろ。台帳に書けば絶対反映されるようにしろ。Issueは台帳に書くまでの仮に過ぎない。台帳を情報の唯一のマスターにしろ。複数の台帳があるだろうが、重複は省いて参照にしろ」「JSONを作るのはいいが、台帳から参照できるようにしろ」

### TRM.ledger-yaml（2026-10-23・有効）

台帳の形式は YAML（CSV でなく）。マスター（人が書く）は全テーブル YAML（1エンティティ1ファイル）。人が編集している JSON（map-ids.json・areas.json・dependency-graph.json など）もマスターの YAML へ合流する。派生物（機械が作る plan・decor-pools・connections・manifest）は JSON のまま（既存ツール・検証・テスト・ゲーム実行側が読むため。先頭メタデータに入力ハッシュ・生成日時・再生成コマンド）。人が読む一覧は台帳からの md ビュー。理由: 決定の逐語・自由記述（複数行）、建物の窓列・部位・時期差分（入れ子）、コメントが CSV では扱いにくい。

> 「csvが本当にいいのか？yamlとかのほうが管理しやすいのではないのか」「JSONもyamlのほうがいいのではないのか」→（提案「人が編集するものは YAML、機械が作る派生物は JSON のまま」に）「よい」
