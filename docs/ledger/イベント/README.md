# イベント台帳の置き場

**置き場: `docs/ledger/イベント/<イベントID>.yaml`。イベント1件につき1ファイル。** ID は出来事が分かる安定した名前とし、発生順をIDやファイル名に埋め込まない。既存 `E001` などは移行元の参照として保持し、新しい場面を途中に追加しても既存ファイルを改名しない。フィールド、戦闘中の発火や前後の会話を区別し、それぞれの範囲と関連を台帳に記す。

[opening_battle.yaml](opening_battle.yaml) は書式の試作。**このディレクトリの台帳は現行の読み込み・検査に未登録**で、形式・台帳ビルド・本番生成器の実装は #254 / #250 の後続作業。現在の `docs/ledger/*.yaml` のフラットな表の読み込みは、このディレクトリへ自動的に対応しない。試作の内容は未決を含み、ゲームで実行しない。

## 台帳と md の関係

- イベントのセリフ・脚本は台帳が正本。各 YAML には、目的、時代・参加者、発火条件、前後関係、量・往復、状態・未決、出典とともに、name-name 記法の脚本原稿を置く設計。
- 生成先は `play/`（入口 `script.md`、共通定義 `data.md`、場面 `events/<イベントID>.md`）。md は台帳から生成するスナップショットとし、先頭に生成物であることを示す。第一歩は E001〜E003 のみ（下の「一枚絵フィールドで動く md の生成」）。レビュー用の `scripts/preview_event.py` とは別。
- 既存 E 番号と名前付きIDの対応、name-name のシーン名とファイル名の一対一対応、戦闘宣言をどの生成ファイルに置くかは、既存データと #250 の方針を照合して実装時に確定する。

## プレビューの生成

[プレビュー生成スクリプト](../../../scripts/preview_event.py) を `uv run python3 scripts/preview_event.py` で実行すると、各イベントのmdと[目次](../../production/event-preview/README.md)・[全編通読用](../../production/event-preview/all_events.md)を生成する。本文・条件・前後関係は人間レビュー用の仮稿。表示順は閲覧用で、ゲームの進行順を確定しない。台帳メタデータと脚本本文の整合、実際の画面表示やゲームへの接続は保証しない。

## 一枚絵フィールドで動く md の生成（#250 第一歩）

`opening_battle`・`evacuation_after_play`・`play_cancelled_promise`（E001〜E003）だけ、[生成スクリプト](../../../scripts/field_md.py) が `uv run python3 scripts/build_ledger.py build` で [`play/`](../../../play/README.md) に name-name の /play 用 md を作る（`check` で鮮度・孤児・上書き防止を検査。単体なら `uv run python3 scripts/field_md.py check`）。入口 `play/script.md`、共通定義 `play/data.md`、場面ごとの `play/events/<イベントID>.md`。**生成物は台帳が正本で、編集しない。** 状態 blocked は解除しない。

- 台帳に足した列（既存の語に寄せた。厳密に判定し、typo は生成時に FAIL）: `背景画像`・`歩行マスク`（`assets/images` からの相対。背景があればマスク必須）・`出現位置`（`x,y`・背景px）・`発火条件`（空欄=別のイベントから起動、または `場面開始・1回` のどちらかだけ。後者で `[トリガー auto … once=true]`）・`行き先`（そのイベント末尾に `[場面移動:]` を足す先のイベントID。到着位置は行き先の `出現位置`）・`暫定`（暫定の正本。生成物の先頭コメントに出る）。
- 暫定の項目と理由は各台帳の `暫定` 列が正本（opening_battle に敵・味方の数値の仮値の説明もある）。味方の魔法・特技は劇戦闘用の具体が台帳に無いので空。
- name-name 側: worker の `sit-by-me` の `scriptsDir: "play"`（name-name #1144）で読まれる。`[場面移動:]` の行き先の読み込みは下記。

## name-name の記法と制約

仕様の正本: name-name リポの `docs/spec/markdown-v0.1.md`「脚本制御の戦闘」「脚本 `.md` で書く」、`docs/design/scripted-battle.md`。

- 会話イベントは `[イベント 名前]` から `[/イベント]`。話者は `**話者**:`、地の文は `>`、待機は `[待機: 400]`。一枚絵フィールドのNPC脚本では会話・地の文・待機・感情が使える。
- 戦闘の宣言は `[戦闘 ID]` から `[/戦闘]`。`敵:`・`味方:`、`台詞:`・`参戦:`・`復活:`・`強制:`・`逃走:`・`終了:` と条件を使う。`[戦闘: ID]` は宣言ではなくイベント中の開始命令で、コロンは半角。
- 戦闘中の条件は `開始`、`ターン>=N`、`HP[id]<=N` 等。戦闘中のルールは行動の境目で評価し、各ルールは一度だけ発動する。`終了: ... 結果=中断` は勝敗なし。結果別に `中断時: 次=...` などを書く。
- 一枚絵フィールドの `[イベント]`（`[トリガー]` や NPC が起こすもの）内の `[戦闘:]` `[NPC移動:]` は name-name の仕様（#1073・#1077）で動く。`[トリガー auto scene=名前 once=true]` は script.md の場面に書ける（`scene=` は必須）。`[場面移動:]` の行き先の場面は、手元の name-name の古い版ではトリガー・NPC が指すイベントからしか辿られず、戦闘結果の `次=` で呼ぶ E002 の行き先（E003 の場面）は読み込まれなかった。name-name の現行 main（2026-11-11 時点）の parser と設定生成では、両方の場面が読み込まれることを確認済み。
- 未確定の数値や未宣言のIDを使った完成品として生成しない。文字数・往復の制約も実表示を踏まえて設計する。

旧 E の棚卸し・進捗: [仮ファイル一覧](../../production/event-planning/README.md)。初期設計: [全体棚卸しと試作](../../production/20261110-event-ledger-design-draft.md)。

## 途中の場面から始める（再開点）

オープニングを毎回通らず、任意の場面から確認するための仕組み（#250）。再開点は `docs/ledger/再開点/<再開点ID>.yaml`（場面ID・位置・向き・パーティ・戦闘）が正本で、[生成スクリプト](../../../scripts/resume_saves.py) が `play/saves/<再開点ID>.save.json` を作る（`field_md.py` の出力に含まれ、`build_ledger.py build` / `check` の対象）。台帳に実在する人物・敵だけを使う。`再開直後` 列（空欄、または `場面開始を起こす`）で、セーブの `field.fireAuto: true`（name-name Issue #1155）を付ける。手順は [play/README.md](../../../play/README.md)。
