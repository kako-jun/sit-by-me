# イベント台帳の置き場

**置き場: `docs/ledger/イベント/<イベントID>.yaml`。イベント1件につき1ファイル。** ID は出来事が分かる安定した名前とし、発生順をIDやファイル名に埋め込まない。既存 `E001` などは移行元の参照として保持し、新しい場面を途中に追加しても既存ファイルを改名しない。フィールド、戦闘中の発火や前後の会話を区別し、それぞれの範囲と関連を台帳に記す。

[opening_battle.yaml](opening_battle.yaml) は書式の試作。**このディレクトリの台帳は現行の読み込み・検査に未登録**で、形式・台帳ビルド・本番生成器の実装は #254 / #250 の後続作業。現在の `docs/ledger/*.yaml` のフラットな表の読み込みは、このディレクトリへ自動的に対応しない。試作の内容は未決を含み、ゲームで実行しない。

## 台帳と md の関係

- イベントのセリフ・脚本は台帳が正本。各 YAML には、目的、時代・参加者、発火条件、前後関係、量・往復、状態・未決、出典とともに、name-name 記法の脚本原稿を置く設計。
- 生成先は `events/<イベントID>.md`。入口は `script.md`、共通定義は `data.md`（#250）。md は台帳から生成するスナップショットとし、先頭に生成物であることを示す。本番生成器と出力先の読み込み・公開経路は未実装・要確認。
- 既存 E 番号と名前付きIDの対応、name-name のシーン名とファイル名の一対一対応、戦闘宣言をどの生成ファイルに置くかは、既存データと #250 の方針を照合して実装時に確定する。

## プレビューの生成

[プレビュー生成スクリプト](../../../scripts/preview_event.py) を `uv run python3 scripts/preview_event.py` で実行すると、各イベントのmdと[目次](../../production/event-preview/README.md)・[全編通読用](../../production/event-preview/all_events.md)を生成する。本文・条件・前後関係は人間レビュー用の仮稿。表示順は閲覧用で、ゲームの進行順を確定しない。台帳メタデータと脚本本文の整合、実際の画面表示やゲームへの接続は保証しない。

## name-name の記法と制約

仕様の正本: name-name リポの `docs/spec/markdown-v0.1.md`「脚本制御の戦闘」「脚本 `.md` で書く」、`docs/design/scripted-battle.md`。

- 会話イベントは `[イベント 名前]` から `[/イベント]`。話者は `**話者**:`、地の文は `>`、待機は `[待機: 400]`。一枚絵フィールドのNPC脚本では会話・地の文・待機・感情が使える。
- 戦闘の宣言は `[戦闘 ID]` から `[/戦闘]`。`敵:`・`味方:`、`台詞:`・`参戦:`・`復活:`・`強制:`・`逃走:`・`終了:` と条件を使う。`[戦闘: ID]` は宣言ではなくイベント中の開始命令で、コロンは半角。
- 戦闘中の条件は `開始`、`ターン>=N`、`HP[id]<=N` 等。戦闘中のルールは行動の境目で評価し、各ルールは一度だけ発動する。`終了: ... 結果=中断` は勝敗なし。結果別に `中断時: 次=...` などを書く。
- 一枚絵フィールドの **NPC脚本内**の `[戦闘:]` と `[NPC移動:]` は現時点で読み飛ばされる。TopDown RPG のイベントからの戦闘開始と混同しない。実際に必要な自動イベントや戦闘接続が sit の一枚絵フィールドで動くかは別途確認する。
- 未確定の数値や未宣言のIDを使った完成品として生成しない。文字数・往復の制約も実表示を踏まえて設計する。
