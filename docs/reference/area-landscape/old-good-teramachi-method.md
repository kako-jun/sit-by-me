## 4. 改善案

### 4.1 モック編集方式を保ったままの変更案（優先順）

(a) **plan の walls / floors / boxes に `look` を書く。語彙は「以前の説明文」から取る。** 入力は台帳 `要素`・`MAP仕様` 等から ledger_build で導出されるので、台帳に書く。
- 塀(top-wall, closure-*, kind=fence): 「寺の土塀。紙粘土を厚塗りし、下半分に荒く描いた石積み、上に笠(波形段ボールの小さな瓦屋根)。壁面に指跡・ヘラ跡・塗りムラ。雪が笠の上に薄く載る」。長塀の一部に「雪囲い／こも掛け(藁の筵の茶色い帯を竹の爪楊枝で留める)」。根拠: 旧 README の語彙、R006「こも掛け、土塀」、sit-diorama の材料表。
- 民家(house-*): 家ごとに個別化(外壁=板張り／漆喰／トタン、屋根=瓦／トタン、玄関前の雪囲い、物置、雪かき道具)。「家ごとに look を変える」を plan に書く(旧 SKILL の「1枚ごとの個性」と同趣旨)。
- 床 road: 「黒い画用紙に薄い透明ニス、中央に消雪パイプの低い散水ヘッドの列(ビーズ)と濡れた艶、脇に薄い雪解け水、タイヤ跡」。snow: 「綿の雪の起伏、土の露出、足跡、除雪の雪山(綿の盛り上がり)、融雪水の筋」。

(b) **境界を『物』として許可する帯を1節足す（BOUNDARY節）。** 例: 「道の縁と雪面の間の帯(道の外周から内側 12〜30px、plan で座標を出す)に、除雪の雪山、赤白スノーポール(爪楊枝にテープ)、電柱(割り箸＋色紙)、側溝/用水の石縁、塀の根元の雪だまりを置いてよい。ただし道の床(歩ける領域)の内側には1画素も出さない」。FORBIDDEN の「歩く床に足さない」と矛盾しないよう、**歩ける床の外側の帯**として座標で定義する(帯の座標は plan と mask から機械的に出せる＝今の COORDINATES と同じ方式。推測: 実装は `oblique_build.py` の拡張が必要)。

(c) **景色の扉を『通行戸口』と別枠にする。** plan に `decor_doors[]`(壁・位置・幅・高さ・状態=閉じた板戸 or 錆びた鉄扉、通行不可)を追加し、DOORS 節を二分: 「ピンク=通行戸口N個(0個なら0個)。それとは別に、塀の面に**閉じた景色の扉**をM個、座標指定で描く。通行はできない、歩行マスクは黒のまま」。現状の「0個。増やさない」が文面でそれを禁じている。

(d) **木の帯を実際に使える幅にするか、木の必須本数を MAP ごとに下げる。** 帯が13〜21pxなら、plan の `tree_zones` を民家の裏・塀の根元など実面積のある矩形に置く(外観 MAP 用に `tree_zones` が既にある。`SKILL.md` に記述)。

(e) **変化の肯定形を C13 型で戻す**: 「綿の雪は起伏があり、茶色い土の露出、足跡、路面の砂・泥・塩の白残り・黒ずみ・錆。点在する数を指定(例: 足跡 6〜10 か所、土の露出 5 か所以上)」。v1/v2 の差が実証した要素(木・土・足跡・汚れ・数)。

(f) **FORBIDDEN を MAP に合う分だけにする。** 寺専用(畳、屋根の外形)や寺町全体の木の洋風禁止は、該当 MAP にだけ出す(`decor_pool` を寺用と街路用に分ける。`teramachi-winter-exterior` は寺境内向きの記述が多い)。禁止の列挙は既存の pitfall(Avoid リストが拒否や逆効果を招く、`pitfalls.md`)に合わせ、肯定形に置き換える。

(g) 検証: TRM-08 の1枚を、(a)〜(e) を入れて 4 テイク。目視で kako-jun が判定(10-23 の決定どおり自動順位づけなし)。幾何保持の測定(窓・戸口・壁の structure)は既存のまま。
