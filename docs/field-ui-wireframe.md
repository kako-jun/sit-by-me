## 1. 画面の系統と画面サイズ

フィールドUIは**2系統**で、混ぜない。

| 系統 | 部品 | 位置づけ | レイアウト基準 |
|---|---|---|---|
| A. フィールド面の重ね部品 | エリア名帯、会話窓 | フィールドの16:9面（以下 面）に重ねる。フィールドは動き続ける／止まったまま見えている | 面基準（W=面の幅、H=面の高さ） |
| B. 全画面メニュー | メニュー画面と各項目画面 | フィールドを占有する**独立した全画面**。フィールドは見えない（暗転して残す背景は置かない） | 背景は端末の画面全体に敷く。UI の配置は16:9の基準面（画面に contain で収めたもの）の比率 |

対象の画面サイズは横長（PC・スマホ横）のみ。縦長（スマホ縦）は考慮しない。


## 2. ワイヤーフレーム

### 2-A. 系統A: フィールド面に重ねる部品（会話窓・エリア名帯）

メニューとは別系統。フィールドの面の上に出る。

#### 2-A-1. エリア名帯（面基準。PC・スマホ横）

```
+----------------------------------------------------------------+
|              +------------------------------+                  |  <- 上端から 3%H
|[残り 04:12]  |        か ら く り 坂         |            [≡]   |  <- 左上: 時間制限中のみ残り時間 / 右上隅: スマホの≡
|              +------------------------------+                  |     帯: 幅 56%W 中央, 高さ 9%H
|                                                                |
|                       フィールド一枚絵                          |
|                                                                |
|                         ( 主人公 )                              |
|                                                                |
+----------------------------------------------------------------+
```

- 帯の幅は 56%W に抑え、左右の隅を他UIに空ける。
- ≡ ボタンは右上隅、一辺 8%H かつ 24 css px 以上（WCAG 2.2 の最小。実ビューポートが小さい場合は 24px を下限に拡大）。
- 時間制限中の残り時間は左上隅（0〜14%W、上端 2%H〜8%H、文字は 16px 以上）に常時表示（systems.md の常時表示）。帯（中央 56%W）・≡（右上隅）と重ならない。

#### 2-A-2. フィールド会話窓（面基準）

主人公が画面上半分（足元 y < H/2）:

### 2-B. 系統B: 全画面メニュー（画面全体基準）

フィールドを占有する独立画面。背景は窓と同じ青系の無地（FF風）。決定済みの配置（右上=項目、左=パーティ縦並び）を保つ。W/H はこの16:9基準面の幅・高さ（以下の %H・%W もすべて基準面の比率）。

#### 2-B-1. メニュー画面（PC・スマホ横）

左のパーティは序盤の4人の例（主人公=オトン／ナムは性別で入れ替わる。decisions.md。壮年編などは章でパーティが変わる）。

```
+----------------------------------------------------------------+
| +--------------------------+              +--------------+     |  <- 上端 2%H
| | [axst] 主人公      Lv 12 |              |>どうぐ       |     |  <- 右上: 項目窓
| |        HP  310 / 310     |              | まほう       |     |     幅 26%W, 2〜90%H
| +--------------------------+              | そうび       |     |     1行 9.3%H x 9行
| +--------------------------+              | アプリストア |     |     手のカーソル(>)は行頭
| | [axst] 幼馴染      Lv 12 |              | まいし       |     |
| |        HP  280 / 280     |              | ジョブ       |     |
| +--------------------------+              | ステータス   |     |
| +--------------------------+              | セーブ       |     |
| | [axst] シャー      Lv 11 |              | せってい     |     |
| |        HP  190 / 190     |              |              |     |
| +--------------------------+              |              |     |
| +--------------------------+              |              |     |
| | [axst] ペー子      Lv 11 |              |              |     |
| |        HP  250 / 250     |              |              |     |
| +--------------------------+              +--------------+     |  <- 両列の下端 90%H
|[◀戻る] 現在地 寺町 | 円 12,300 | 時間 03:21     (PC: Z決定 X戻る)|  <- 91〜99%H: 情報帯+操作の案内
+----------------------------------------------------------------+
```

- 左: パーティ4枠の縦並び（幅 62%W、上端 2%H〜90%H、1枠 約 21.5%H）。アクスタはフィールドと同じ姿。
- 右上: 項目窓（9行、上端 2%H〜90%H）。下端: 情報帯（現在地・円・プレイ時間）と操作の案内、左端に「◀戻る」ボタン（8%H）。
- 時間制限中は、情報帯の「時間」を「残り 04:12（停止中）」に替え、タイマーがメニュー中は止まっていることを見せる（3-6）。
- **タップ寸法の根拠**: 項目 1 行 9.3%H。スマホ横の基準面の高さはブラウザの UI で 390px 未満（320〜390 css px 程度の想定値。画面全体の高さではなく16:9基準面の高さ）になりうるので、その場合 30〜36px。タップ対象の最小寸法は WCAG 2.2 の最小 24 css px を下限とし、行全体（項目窓の幅いっぱい）を押せる範囲にして横幅で補う。「◀戻る」ボタンも高さ 8%H（下限 24px）以上。誤タップ防止のため、項目は「タップでカーソル移動、もう一度タップで決定」ではなく**1タップ決定**とし、各画面は必ず「◀戻る」で戻れる。

## 3. 「決めること」各項目の内容（推奨案を 2026-10-29 に一任で確定）

### 3-1. エリア名帯

| 項目 | 推奨案 | 理由 |
|---|---|---|
| 表示秒数 | **保持 2.5 秒**（出 0.3 秒＋保持 2.5 秒＋消 0.4 秒 = 約 3.2 秒）（決定 2026-10-29、kako-jun 一任） | 決定済みの「数秒」の中央値。2〜3 秒でエリア名（短い名前）は読める。長すぎると操作の邪魔になる |
| 出入りの演出 | **上端からスライドイン＋フェード、フェードアウト**（決定 2026-10-29、kako-jun 一任） | 戦闘・メニューと同じ窓の動きに揃う。#847 の枠スライドと同系統 |
| 連続移動 | **即差し替え**。表示中に別エリアへ入ったら、帯を消さずに文字だけ 0.15 秒でフェード差し替え、保持時間を再開始。同名エリアへ戻っても出さない。キューは作らない（決定 2026-10-29、kako-jun 一任） | 古い名前を待たせると現在地と食い違う。素早く通過するだけの時は最新だけ見せればよい |
| 出さない時 | 戦闘中・メニュー中・会話窓表示中・イベント演出中は出さない。会話が始まったら出ている帯は即フェード。セーブ読込後の最初の画面では出す（決定 2026-10-29、kako-jun 一任） | 帯は情報であり、主役（会話・演出）を妨げない。ロード直後は現在地の確認になる |
| 操作 | 操作を止めない（非モーダル）。タップで早く消せる | 歩きながら読めるため |

### 3-2. 会話窓の上下判定

| 項目 | 推奨案 | 理由 |
|---|---|---|
| 基準点 | **主人公アクスタの足元（接地点）の y** と H/2 を比較 | 歩行マスクの基準と同じで安定。頭の位置は絵・ポーズで変わる |
| ちょうど中央（y = H/2） | **下側**に出す（決定 2026-10-29、kako-jun 一任） | 会話窓は下が標準（FF・DQ）。上半分=下側の決定と連続させ、境界を「下半分から上側」にする |
| 判定のタイミング | 会話の開始時に決め、同じ会話の間は固定。イベントで主人公が動いた時だけ、ページ送りで再判定し 0.15 秒でスライド移動 | 会話中に窓がパタパタ動くのを避ける。ヒステリシス（遅延判定）は不要（動かないので） |
| 安全弁 | 選んだ側の窓がアクスタ矩形と重なる時（大きな絵・画面端）は反対側へ。それでも重なる場合は上下判定を優先 | 「アクスタを隠さない」の決定を守る |
| 窓寸法 | 幅 94%W、高さ 28%H（名前行＋本文3行）、画面端から 3%H。名前は窓内の左上の1行に入れる（外側タブにしない。決定 2026-10-29、kako-jun 一任） | 3行で足りる文量。上側表示で画面端 3%H でも名前が切れない。端の余白はFF風 |
| 他UIとの干渉 | エリア名帯が出ている時に会話が始まれば帯を消す。感情吹き出し（#170）は会話窓表示中は出さない。**上側に出る会話窓（3〜31%H）は左上の残り時間・右上の≡と重なる。残り時間は脱出に関わる情報なので、会話窓の上に重ねて描き続ける（隠さない）。時間制限中の上側表示では、名前行の開始位置を左 16%W 以降にずらし、残り時間と重ならないようにする。≡ は会話中は無効かつ非表示** | 同じ上端・主人公周辺を取り合わないため |

### 3-3. メニュー項目と順序（FF5 の構成を本作に合わせる）

FF5 の参照元は公式 PS Anthology マニュアル（ファイル名 38706_us-Final-Fantasy-Anthology-Final-Fantasy-VI.pdf。実体は FF5）。

原文引用（p.5〜6）:

> The Menu Screen consists of character data and four windows. 1. Job/Ability Window 2. Menu Command Window 3. Time Window 4. Money Window

要約（引用ではない）: メニューコマンド窓のコマンドは アイテム・まほう・そうび・ステータス・コンフィグ・セーブ。ジョブ・アビリティはコマンド窓とは別の窓で扱う。並び替え（p.6 FORMATION CHANGES）は、方向キー左で Order が現れる操作。

FF4 の構成は出典未確認のため参照しない。FF6 は SNES 一次資料未確認。本作は、アビリティが刀アプリ、装備がアプリストア、魔石・ジョブがある点で変える。

| 順 | 項目 | 内容 | 根拠 |
|---|---|---|---|
| 1 | どうぐ | イマジナリー宝箱で得たアイテム。つかう・せいとん・たいせつなもの（3-5） | FF5 の先頭（アイテム）。使用頻度が高い |
| 2 | まほう | 共有ライブラリの確認と、回復など使える魔法の使用 | 魔法は全員共有で、装着枠なし |
| 3 | そうび | 人物ごとの刀（スマホ）・防具（タブレット）の持ち替え。装備中アビリティの確認 | 持ち替えはいつでも（決定済み）。アビリティはここで見る |
| 4 | アプリストア | 刀・防具の購入・強化（円） | 決定済み。商店は店でなくメニュー |
| 5 | まいし（項目の置き場は仮。魔石の装備が別枠か否かは systems.md #134 要確認で未決） | 魔石の装備（人物ごと）。属性は魔石とタブレット防具を合わせて 2 つまで。装備枠の数は未決 | #134 の決定（systems.md）。枠数は要確認（創作しない） |
| 6 | ジョブ | 戦闘ジョブ・フィールドジョブの変更 | 刀・ジョブの切替はメニューから（ability-candidates §5-2c） |
| 7 | ステータス | 人物ごとの能力・固有素質・想像の刃 | FF5 のコマンドにもある。パーティ枠のタップでも開ける |
| 8 | セーブ | スロット選択。時間制限中は灰色で選択不可 | 決定済み |

- アプリストア・まいし・ジョブは、解禁前でも項目を出して灰色にする（使えない項目は暗く、という FF5 と同じ扱い。選ぶと理由を説明バーに出す）。解禁時期は未決（systems.md・decisions.md 末尾のとおり）。

- 「アビリティ」は独立項目にしない。アビリティは刀アプリ側（そうび・ステータスで確認）。
- 項目の順序・内訳は 2026-10-29 に一任で確定。項目は定義側データで増減できる形にする（#880 の方針）。

### 3-4. 選択中の見せ方

- 項目: 手の形カーソル（#744）を行頭に出す。文字は白のまま。選択不可は灰色。
- パーティ枠（装備・ステータスなど人物を選ぶ時）: 戦闘の決定と同じ「いま選択中」表示をそのアクスタに出す。矢印は使わない。選択中でない枠は暗くせず、選択中の枠を明るく（光らせる）見せる（過去の方針: 既読・完了は暗くせず灯す）。
- 項目選択中、左のパーティには何も強調しない（人物を選ぶ段階に入って初めて強調）。

理由: カーソルは #744 で決定済み。人物の選択表示は戦闘と同じにしておけば、プレイヤーは1つの見方を覚えるだけで済む。

### 3-5. 各項目画面の構成

共通: 親の項目窓が消え、枠が右上から必要な位置へスライドして再利用される（#847 の FF4 風遷移に合わせる。#847 が未実装でも、通常の差し替えで機能は成り立つ）。上端に説明バー、下端に操作の案内。

| そうび | 左: 人物選択 → 右: 2枠（刀=スマホ／防具=タブレット）と所持アプリ一覧。変更前後の差分を表示 |
| アプリストア | タブ「刀／防具」。一覧に値段（円）・所持済み印。購入は確認窓（「買う／やめる」）。所持金は常時表示 |

### 3-6. 開閉・戻る操作

| 操作 | PC | スマホ |
|---|---|---|
| 開く | Esc / X / M（フィールド上のみ） | フィールド面の右上隅の小さなメニューボタン（≡）をタップ。帯と重ならない |
| 決定 | Z / Enter / クリック | 1タップ |
| 戻る（1階層） | X / Esc / 右クリック | 全画面メニュー内の左下「◀戻る」ボタン（情報帯の左端） |
| 閉じる | 最上位で戻る操作（X / Esc / 右クリック）の結果としてのみ閉じる。Esc で一気に閉じない | 最上位で「◀戻る」（≡ は全画面メニュー中は見えないので使わない） |

- PC の M はフィールド上で開く専用で、メニュー内では使わない。メニュー内の戻るは X / Esc / 右クリックのみ。右クリックはフィールド上では何もしない。
- 戻るは必ず1階層ずつ。最上位（項目窓）で戻るとメニューを閉じてフィールドに戻る。
- 全画面メニュー中は窓の外タップによる戻りはない（全画面で窓の外が無いため）。戻る手段は「◀戻る」ボタンのみ。
- 会話中・イベント中・演出中・戦闘中は開けない。
- 操作の案内は常に画面下端に出す（#880 の要件）。PC はキーのヒント（Z決定 X戻る）、スマホは「◀戻る」ボタン。
- メニューボタン（≡）の位置（右上隅）とキー割当は 2026-10-29 に確定。ただし移動用の仮想パッドと干渉する場合は、実装時に位置を調整する。
- **時間制限中（トクリュウ脱出）のメニュー中のタイマー: 停止**（2026-10-29 に一任で確定。推奨どおり）。理由: メニューで持ち替え・購入するのが本作の要で、操作の遅いスマホが不利になるのを避けたい。ただしアイテム整理で時間を稼げるため、**プレイ検証で変更の余地あり**。
- **時間制限中の残り時間表示**: systems.md の「画面にデジタル残り時間を常時表示」は、フィールドでは面に重ねて出す。全画面メニュー中は、情報帯の「時間」を「残り mm:ss（停止中）」に替えて出し、止まっていることを見せる。

### 3-7. 全画面メニューと戦闘ウィンドウの共有範囲

| 区分 | 共有する | 共有しない |
|---|---|---|
| 見た目 | 青グラデーション・白枠・白文字・手のカーソル・角丸・枠の太さ・文字の大きさの基準（H 比） | |
| 部品 | リスト窓の行高・余白・スクロール、確認窓（はい/いいえ）、説明バー、「いま選択中」のアクスタ表示 | |
| 動き | 窓の出入り、#847 の枠スライド遷移、決定・戻るの効果音 | |
| 配置 | | 戦闘は下にコマンド・ステータス、上にメッセージ帯。全画面メニューは右上項目・左パーティ。画面ごとに配置は別 |
| 内容 | どうぐ・まほうの一覧部品は同じ。ただし戦闘の一覧は戦闘用の絞り込み | 戦闘のコマンド窓、ATBゲージ、ダメージ数字 |

全画面メニューと戦闘画面は別画面。共有するのは窓の部品（配色・枠・カーソル・リスト窓・確認窓・説明バー）と動きだけで、画面全体の構成は共有しない。エリア名帯・会話窓も同じ部品を使う。

理由: 「色だけテーマ、寸法は共通」の決定どおり、寸法・部品は1セットにして画面ごとの場当たりな差を防ぐ。配置は画面の役割が違うので共通にしない。
